# ADR 023 — 提示词改为 coding-first

**状态：** 已接受
**日期：** 2026-11-02
**相关：** ADR 011（提示词是一份文档）、ADR 017/018（沙箱）、ADR 021（task CWD）、
ADR 022（本机权限控制面）

---

## 1. 决策

活动 system prompt 从“陪伴者人格”换成“会写代码的 agent”：

- **保留**：Eunoia 的名字、中文回复、长期记忆、安全规则。
- **删除**：Fi / Ne / Si / Te 四种视角、五条陪伴原则、陪伴示例。
- **新增**：工具纪律、代码工作方式、输出规则。

原人格提示词完整归档在 `src/agent/prompts/companion.personality.md`，不删。回滚就是
把它复制回 `companion.md`，重新构建、重启。

## 2. 背景

产品实际使用已经从“聊感受”转向“在项目里干活”，而活动提示词仍以人格为主：
四种视角、五条原则、示例占了大半篇幅，工具规则只有一小节。编码回合里这些内容
是噪声，还会挤掉真正该说的工具纪律。

一次真实故障说明了缺什么：模型在 `/workspace/src/models` 下执行相对的
`rm -rf snake`，`rm -rf` 对不存在的路径也退出 0，模型据此报告“已删除”，而真正的
`/workspace/snake` 分毫未动。旧提示词里甚至写着“不要用绝对路径”，进一步加剧了
路径基准的混淆。

DSH 的提示词被拿来参考。需要说清楚的是它到底是什么：实际发给模型的那份只有约
5.8k 字符，主体是**工具纪律 + 环境说明**，不是代码风格指南。可复用的是“用对工具、
先读再改、检查退出码、先给结果”；不能复用的是它的工具名（`bash`、`read`、`edit`、
`job_output`、`subagent`、`workflow`）、环境描述和英文人格。

## 3. 新文档的结构

| 段 | 作用 |
|---|---|
| 身份 | Eunoia + 会写代码 + 中文 + 不客套 |
| 工作方式 | 先看再说、最小改动、改完验证、退出码 0 不等于完成、不确定就问 |
| 工具纪律 | `glob` / `grep` / `read_file` / `edit_file` / `write_file` / `run_command` / `change_directory` / `load_skill` 的用法；两个路径基准；不可逆操作用绝对路径并确认目标 |
| 输出 | 先结果后解释、路径和行号、说清验证了什么、不贴整份文件 |
| 记忆规则 | 压缩成一节：什么时候搜、存、更新；来源诚实；检索结果是片段 |
| 安全 | 危机处理保留，安全优先 |
| 现在的上下文 | 解释每轮附加的时间、关系、叙事背景，避免被当成用户发言 |

记忆与安全不是可选项：记忆工具仍然暴露给模型，安全层仍然会注入危机指令；提示词
不解释它们，模型就只能在两个都看不见的地方猜。

## 4. 测试策略

- **旧的人格规格测试改为读备份文件。** Fi / Ne / Si / Te、五原则、安全优先这些
  断言继续守着 `companion.personality.md`——备份也要保真，否则回滚回到的是一份
  没人检查的文档。
- **新增 `tests/agent/prompt-coding.test.ts`。** 活动提示词必须提到模型真实拥有的
  工具、两个路径基准、不可逆操作规则、记忆与安全；不能再出现四种视角。
- `prompt-language` / `prompt-version` / `prompt-source` 继续约束活动文档：中文、
  哈希、结构、加载器里没有内嵌文案。

## 5. 后果

- 编码回合的提示词更短、更直接；陪伴式的默认行为（视角、语气）不再自动出现。
- 记忆与安全保留但压缩成规则，不再主动展开。
- `PROMPT_VERSION` 随文档变化；`eval --replay` 对旧录制无效，要比较行为需要一次
  live 评测。
- 回滚成本很低：复制备份文件、构建、重启。

## 6. 工具描述

活动提示词换成 coding-first 之后，工具描述也按 DSH 的形状重写：**一句到几句的契约**
——它做什么、返回什么、哪一两条约束是 schema 表达不了的。“什么时候调用”移到提示词的
「工具纪律」，不再在每个工具里重复一遍。

- 参数描述改成一行，路径参数明确写出基准（工作区根目录 / 当前任务目录）。
- 没有照搬 DSH 英文原文：语言不同，工具名和语义也不同（`bash` 没有 `workdir`、
  Eunoia 的 `read_file` 用 `start/end`）。借鉴的是结构，不是句子。
- 记忆工具没有 DSH 对应物，但也缩短了；什么时候该搜、该存、该更新，现在由提示词的
  记忆段统一说明。
- `tests/tools/descriptions.test.ts` 守住两点：描述不重新长成“什么时候调用”清单，
  以及 run_command / change_directory 的路径基准和不可逆操作规则还在。

## 7. 不做什么

- **不照搬 DSH 原文。** 它的工具名和环境与 Eunoia 不匹配；照搬会让模型调用不存在
  的工具。
- **不新增工具。** 这次只改提示词；路径统一（让文件工具也接受 `/workspace/...`）
  仍是独立决策。
- **不删人格文档。** 它是回滚路径，也是产品历史的一部分。
