# ADR 026 — 消息操作栏、重新生成与附件上传

**状态：** 已接受
**日期：** 2026-11-03
**相关：** ADR 006（客户端/服务端边界）、ADR 014（agent loop）、ADR 016（SQLite）、
ADR 025（打断与继续）

---

## 1. 决策

每条助手回复下方提供一条操作栏：

| 动作 | 行为 |
|---|---|
| 复制 | 复制原始 Markdown（已有，改为图标按钮） |
| 朗读 | Web Speech API，`zh-CN`，再点一次停止 |
| 导出 | `navigator.share`，不可用时下载 `.md` |
| 重新生成 | 删除当前回复，重跑上一条用户消息 |
| 更多 | 复制纯文本、导出整段对话 |

输入框新增附件按钮：

- 通过 `POST /api/uploads` 上传文件；
- 文件写进**当前会话的工作区**，模型用 `read` / `bash` 读取；
- 发送时只传工作区相对路径，附件列表随本轮尾部上下文给模型；
- 单文件 10 MB、最多 5 个，文件名经过清理。

## 2. 背景

聊天页此前只有「复制」文字按钮和评分按钮。用户给出的参考是一个标准的消息操作
栏：复制、朗读、分享、重新生成、更多；同时指出没有上传入口。

三件事决定了实现方式：

1. **这是本地单用户产品。** 没有公网地址可以分享，所以「分享」是 Web Share 或
   下载文件，而不是生成一个链接。
2. **模型是纯文本的。** `model-port.ts` 只支持 text / function call / result；图片
   不能作为视觉输入。附件因此只能作为**工作区里的文件**存在，提示词必须明确
   告诉模型"图片只能当文件处理"，否则它会假装看过。
3. **重新生成必须复用 `runTurn`。** 另写一条生成路径会让打断、安全缓冲、持久化
   和评测逻辑分叉；正确做法是让 `runTurn` 支持"不追加用户消息、读取最后一条
   用户消息"这一种模式。

## 3. 重新生成

### 3.1 服务端

`POST /api/chat/regenerate`，body `{ conversationId, turnId? }`：

1. 校验会话属于当前用户；
2. `SessionService.rewind()` 找到最后一条用户消息，删除它之后的**所有**消息；
3. 如果最后一条用户消息已经落在摘要边界之前，拒绝（409）——模型不会重放它，
   重生成会答非所问；
4. 如果没有可删除的回复，拒绝（409）；
5. 用与 `/api/chat` 相同的 SSE 通道跑 `runTurn({ regenerate: true })`。

`runTurn` 在 `regenerate` 模式下：

- 不追加新的用户消息；
- 从数据库读取最后一条用户消息作为本轮输入；
- `protectSeq`、历史过滤、`sourceMessageId` 都指向同一条消息；
- 仍然走检索、安全检查、工具、持久化和中断路径。

### 3.2 客户端

- 只有**最后一条**助手消息显示「重新生成」；开始新一轮时，旧按钮被移除。
- 点击后先移除该回合的 DOM，再请求 SSE；服务端删除旧回复后流式返回新回复。
- 失败时旧回复已经不在，界面显示错误气泡；这是"替换"语义的代价，换来的是
  不会出现两条并存的回复。

### 3.3 没有做什么

- **不保留旧回复做撤销。** 需要的话可以在删除前写一条 `agent_runs`，但目前运行
  记录已经保留了旧回合的统计。
- **不在客户端判断"能不能重新生成"。** 权威判断在服务端：摘要边界和"没有回复"
  都只有数据库知道。

## 4. 附件上传

### 4.1 为什么不用 multipart / base64

- multipart 需要一个解析器，而项目没有这个依赖；
- base64 会把 10 MB 文件变成 13 MB JSON，还会撞上聊天的 64 KB 请求体上限。

所以上传是一条独立路由，body 是原始字节：

```
POST /api/uploads?conversationId=<uuid>&name=<urlencoded>
Content-Type: <文件类型>
<bytes>
```

返回 `{ attachment: { path, name, mime, bytes } }`。

### 4.2 为什么写进工作区

agent 的 `read` / `bash` 运行在只挂载任务工作区的容器里。把文件放在宿主机
`data/uploads` 下，模型根本看不到；放在工作区里，它就能像读项目文件一样读。
部署是 bind 模式时工作区就是项目根，因此附件落在：

```
<workspace>/.eunoia/uploads/<conversationId>/<name>
```

仓库的 `.gitignore` 忽略 `.eunoia/`；它不是源码。路径不加入
`DEFAULT_IGNORED_DIRS`，否则 agent 也读不到。

### 4.3 安全与边界

- 文件名只取 basename，去掉控制字符，最长 120 字符；
- `.env` / `.env.*`、`id_rsa` / `id_ed25519`、`*.pem/.key/.p12/.pfx/.cer` 直接拒绝：
  工作区的读工具本来也会拒绝它们，存下来只是泄漏；
- 同名文件加 `-1`、`-2` 后缀，不覆盖；
- 单文件 10 MB；聊天请求最多 5 个附件；
- `attachments` 只接受 `.eunoia/uploads/<当前会话>/<单层文件名>`，并 `realpath`
  校验仍在目录内，防止符号链接逃逸；
- 附件**不随消息入库**：刷新后文件还在工作区，但历史消息不显示附件条。要持久化
  需要给 `messages` 加列，留给后续。

### 4.4 模型看到什么

尾部上下文新增一段：

```
# 用户上传的文件
这些文件已经放进工作区，下面的路径相对于工作区根目录。需要时用 read、glob 或 bash 查看。
图片不会作为视觉输入送给你，只能当文件处理；不要假装看过图片里的内容。

- .eunoia/uploads/<cid>/shot.png（image/png，142.0 KB）
```

不内联内容：一个 10 MB 附件塞进提示词的后果比它解决的问题严重得多。

## 5. 朗读、导出、更多

- **朗读**用 `window.speechSynthesis`，语言固定 `zh-CN`；代码块替换成"（代码略）"，
  逐字符朗读代码没有价值。再次点击或开始另一条朗读会 `cancel()`。
- **导出**优先 `navigator.share`；用户取消（`AbortError`）不触发下载。没有
  Web Share 时用 Blob + `<a download>` 下载 Markdown。
- **更多**菜单提供"复制纯文本"（去掉 Markdown 标记）和"导出整段对话"（读
  `/messages` 拼成 Markdown）。

## 6. 测试

- **web**：朗读调用与停止、分享调用、更多菜单复制纯文本、重新生成替换而不重复
  用户回合、上传后附件条出现且 `/api/chat` 带上路径。
- **api**：上传落盘与响应形状、`.env` 拒绝、无工作区时 400、附件路径进入上下文、
  重新生成后消息数为 2（替换而非追加）、空会话 409、请求校验。
- **service**：`regenerate` 不追加用户消息、历史不重复、最后一条用户消息作为
  本轮输入；附件上下文包含路径、大小和"不是视觉输入"。
- **db**：`lastUserMessage` / `deleteMessagesAfter` 只删除用户消息之后的尾巴。

## 7. 后果

- 重新生成是破坏性的：旧回复在请求成功前就被删除，模型失败时不会恢复。
- 附件是工作区文件，不是聊天记录的一部分；换会话或刷新后需要重新引用路径。
- 上传依赖工作区/沙箱；未配置时返回 400，而不是悄悄存在一个模型看不到的地方。
- 朗读与分享是浏览器能力；不支持时给出提示或退回下载，不影响其它操作。
- `.eunoia/uploads` 会成为工作区里的真实目录，但被仓库忽略，也不会被复制模式
  的初始快照排除（它是运行期数据，不是源文件）。
