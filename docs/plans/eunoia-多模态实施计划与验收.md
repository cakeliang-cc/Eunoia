# Eunoia 多模态实施计划与验收

> 状态：待 DSH 实施。日期：2026 年 11 月 8 日。
> 交付目标：可替换模型的图片输入链路，包括上传、历史、模型请求、预算与前端反馈。
> 入口：本文是执行计划；[接口设计](../design/eunoia-多模态接口设计.md)解释背景；[图片 Token 与请求预算](../design/eunoia-图片Token与请求预算.md)规定计数与放行规则。三篇有冲突时，以本文及预算文档的明确验收约定为准。

## 交给 DSH 的任务说明

按本文逐阶段实现并交付代码、迁移、测试与验收证据。首期实现用户文本与静态图片输入、助手文本输出，保留音频视频的扩展边界。实现要让更换模型主要发生在模型配置、媒体策略和协议适配器中，前端和消息数据库不使用 DeepSeek 专属结构。

当前另一个 Agent 正在处理会话并发、请求幂等、恢复、完成状态和循环预算。开工先查看最新 diff、相关端口和测试，保留这些改动；复用其 requestId、turn admission、finish reason 和预算入口。不要覆盖文件恢复到本文编写前的状态。共享接口以已落地代码为基线，记录最终衔接差异。

观察时 SQLite 已为版本 8，且仍有并行修改。迁移使用实施时的下一个可用版本，不能硬编码“本次必为 v9”。本任务交付前运行现有检查；文档里的类型为契约草案，允许适应现有命名，但不可改变语义。

## 一期范围和完成定义

必须完成：私有不可变图片资源、有序内容块、消息与资源关联、图片预览、重新生成与续聊回放、模型能力检查、协议转换、请求体与 Token 双预算、错误恢复及离线和真实端点小规模验收。

一期仅接受 JPEG、PNG、WebP 的静态图。SVG、动画 GIF/WebP、多页图像、PDF、音视频不作为视觉输入；明确提示支持范围。已有普通文件上传和文本工具工作流继续可用。图片生成、OCR 桥接、自动跨模型路由、实时语音、视频帧抽取和大型 Bench 不在本期。

交付不能只做到“前端能上传”或“模型请求不报错”。必须证明模型请求包含可解码图片，历史重放引用同一原图，不支持图片的模型不会静默获得删图后的请求。

## 开源实现的借鉴与选择

| 实现 | 已核实的做法 | Eunoia 的选择 |

## 架构与文件落点

```text
前端草稿和图片资源 ID
    ↓
API 结构校验、归属校验、能力与请求预检
    ↓
会话 admission 和消息资源绑定
    ↓

    ↓

    ↓

    ↓
```

建议增加 `src/media/`（类型、存储、验证、变体）、`src/agent/content.ts`（内部内容块）、`src/agent/request-plan.ts`（请求计划）。模型专属处理和计数放 `src/provider/<provider>/` 或现有适配目录。不要让 `web`、`session`、`db` 引入供应商 SDK。

现有修改点包括 `src/api/server.ts`、`src/session/{types,store,service}.ts`、两种 Store、`src/agent/{model-port,model-turn,infp-agent}.ts`、`src/models/{types,catalog}.ts`、`src/provider/`、`web/{app.js,index.html}`、备份和保留清理脚本。

## 稳定的数据契约

### 用户内容与模型路由

```ts
type InputPart =
  | { readonly type: 'text'; readonly text: string }
  | { readonly type: 'image'; readonly assetId: string };

interface UserContentV1 {
  readonly version: 1;
  readonly parts: readonly InputPart[];
}

type Support = 'supported' | 'unsupported' | 'unknown';

interface RouteCapabilities {
  readonly input: { text: Support; image: Support };
  readonly output: { text: Support };
  readonly tools: Support;
  readonly imagePolicyId?: string;
  readonly policyRevision: string;
}
```

内容块保持原始顺序，图片说明放在相邻文本块中。首期 fidelity/detail 由模型媒体策略固定，不对外暴露供应商专属枚举。系统提示、reasoning 与助手文本保留自己的角色约束，不能允许客户端构造 system 图片块。

可用图片能力是模型声明、所用协议适配器和资源处理能力的交集。未知能力按不支持新图片请求处理；不能仅凭名称含 vision、SDK 类型支持或 `/models` 返回了模型 ID 就放行。

同时检查本轮 Agent 是否需要工具调用及所选路由能否承载这些工具；不能为通过图片校验而暗中丢掉 tools。纯看图模式若要禁用工具，应成为显式产品配置，而非适配器的隐式降级。

业务层引用不透明 `assetId`。不保存 `image_url`、Base64、供应商 file_id 或可变工作区路径作为图片事实来源。未来新增模型通过注册模型配置和适配策略接入；用户可配置的能力声明需要清楚标记来源，不向前端暴露密钥和 baseURL。

### 媒体存储与消息迁移

新建私有媒体资源记录：ID、userId、conversationId、实际 MIME、原始/归一化尺寸、字节数、SHA256、存储键、状态、创建时间。消息保存版本化内容块，另维护消息与资源引用关系，覆盖重新生成、历史和删除。先采用会话内资源归属，不支持跨会话复用 ID。

在现有 `messages` 上新增可空的结构化内容列并保留 `content` 文本投影以兼容 UI、导出和搜索。旧行为空时确定性解释为一个 text 块。新行以结构化内容为事实来源，文本投影由同一存储操作派生；不允许客户端分别修改两份内容。SQLite 和 InMemoryStore 执行相同契约。

图片上传独立于沙箱：目录位于配置的数据根下，例如 `data/media/`，进程私有权限；前端只见 ID。原始字节与归一化/请求变体分别保存，原图不可变，变体 key 包含内容摘要、处理器版本及策略版本。工作区只保留按需副本，不改变聊天历史的图片内容。

使用成熟解码库（建议评估 sharp）实际解码验证、处理 EXIF 方向、限制尺寸/像素和检测多帧。发布依赖和构建产物应可在目标 Node 环境运行。不得只按扩展名或浏览器 MIME 判断。临时写入、校验、原子改名和数据库登记需要有失败清理路径。

解码器在分配整张像素缓冲前启用像素限制；有界读取、错误超时和取消均需清理。归一化派生图去除不需要的 EXIF/GPS，原始图保持私有。迁移在事务内完成，模拟中途失败后可再次启动；未知内容版本明确拒绝，不静默当成空文字。

一期产品限制：每消息最多 5 张；原文件每张最多 10 MiB；一次消息原文件合计最多 20 MiB；单边最多 8192、总像素最多 40,000,000。处理队列最多同时解码 2 张。请求阶段还要遵守当前路由的限制，取产品与路由限制的更严格值。所有数值通过服务端公共限制接口给前端，前端不再维护另一份常量。

普通请求变体可按策略限制长边为 2048、保持比例、不放大小图，实际编码尺寸必须落到变体记录。任何有损缩放在预览处说明，保留原图；高细节策略以后由路由扩展。不要把 2048 写进通用消息类型或 Token 算法。

### 上传和预览 API

增加独立 `POST /api/media/images?conversationId=...&name=...`，请求体为原始字节，复用现有身份、Host、同源和 JSON/原始内容路由边界。响应 `201 { asset: { id, name, mediaType, bytes, width, height, status } }`。前端先创建会话，随后上传；不在首次发言前要求配置沙箱。

增加 `GET /api/media/images/:id` 供预览。校验当前用户和会话可访问性，返回正确 MIME、`nosniff`、私有不缓存策略；不透露文件系统路径。不要给浏览器公开可被模型或远端随意抓取的公网资源 URL。

增加 `GET /api/media/capabilities` 或扩展现有模型 API，返回产品上传限制及每个模型的输入能力、可用状态和策略修订。UI 只使用这里的声明。未配置真实 Provider 的测试可用假路由。

`DELETE /api/media/images/:id` 只释放当前未绑定草稿资源；已被消息引用返回 409。消息/会话删除按引用关系释放资源，活动请求期间保留租约；后台/手工清理可以删除超过 24 小时的未绑定资源与已释放资源，不能扫描文件名就删除。

新图片上传失败保留用户本地选择以便重试；服务端不保留半文件。旧 `/api/uploads` 保留普通文件行为；旧图片路径可以继续作为工作区文件附件，但不悄悄升级为视觉输入。前端新图片按钮仅走媒体 API。

### 聊天、回放与幂等

`POST /api/chat` 新增 `content: UserContentV1`，新客户端使用它，普通附件仍可携带现有非视觉 `attachments`。旧 `message` 路径继续接受，服务器转成 text 内容。客户端同时提交 `message` 和 `content` 返回 400，消除双重事实。

只有图片、没有文字时允许发送：至少一个非空 text 或合法 image 块即为有效输入。不得在保存时给用户编造一条文字；若需要默认分析提示，只作为明确的本轮指令使用。

入场顺序：结构/归属/能力预检 → requestId 语义 → 会话 admission → 保存用户消息并绑定资源 → 编排模型步骤。复杂异步预处理在持锁前进行，提交时重新校验资源和路由版本；失败则释放锁/租约。无效请求不追加消息，不留下 running 回合。

requestHash 对规范化内容块、顺序、资源不可变摘要、附件及操作类型计算；一次请求固定的模型路由存入 turn。重试相同 requestId 时复用已固定计划/结果，不能因为会话模型后来改变就偷偷重跑新模型。不同内容复用 ID 仍按现有幂等契约冲突。

重新生成使用最后用户消息的结构化内容及其媒体引用，不依赖浏览器再次提交图片；先完成兼容性和资源预检再改写旧回复。失败时保留原回复。继续、断线后恢复和进程恢复都能找到同一组资源，不能因为只有文本被持久化而丢图。

消息读取 API 返回 `content` 文本投影、`contentParts` 或等价版本化结构，以及授权后可展示的资源元数据。所有展示入口统一使用结构化渲染函数，包含即时发送、历史加载、重新生成和继续；文本复制/Markdown 导出给出“图片附件：名称/不可公开ID”，不导出 Base64 或机器路径。

## 模型不兼容时的明确措施

| 情况 | 服务端行为 | 前端行为 |
| --- | --- | --- |
| 当前模型 image=unsupported | 图片请求 422 `MODEL_INPUT_UNSUPPORTED`，零模型调用 | 提示换兼容模型或移除草稿图片，保留原草稿 |
| image=unknown 或没有可用图像计数/编码策略 | 422 `MODEL_CAPABILITY_UNKNOWN` | 显示能力未配置，不把未知伪装成永久不支持 |
| 当前草稿有图时切到文本模型 | 可以保存模型选择，但发送被阻止 | 显示草稿与模型不兼容，不删除图片，不自动切回 |
| 新消息无图，但实际回放窗口包含历史图 | 对完整输入进行同样预检；422 含 `scope: history` | 提供切换模型或新建纯文本会话；不改旧消息 |
| 图片已归档为明确标记的文字摘要且本次不再发送图 | 按本次真实请求判断，可走文本模型 | 不能宣称文本模型看过原图；要重新看原图时再选视觉模型 |
| 上传成功，发送前资源被删除或模型改变 | 在入场/提交阶段拒绝，不能读取过期计划 | 保留可恢复草稿并给出具体原因 |
| 端点明确拒绝图像/格式 | 以结构化错误结束已接受回合，保留输入和媒体，不自动删图重试 | 显示 Provider 与能力不一致，允许手动换模型 |
| 429、401、网络超时或 5xx | 保留其原始错误类别；不把图像能力改成 unsupported | 显示认证、限流或网络问题 |

支持模型建议只列已声明且已配置可用的路由，不发起未授权的第二次模型调用。默认不做 OCR、不自动跨供应商发送图片、不修改历史以便“兼容”。后续降级若实现，需要显式操作、派生内容来源和单独预算。

错误体统一 `error: { code, message, retryable, details }`；新前端兼容旧字符串错误。details 可包含 modality、当前 modelId、scope、资源块索引和可用模型 ID，不包含原始字节、路径、密钥或第三方响应正文。

新错误分类：400 内容结构错误，404 无权访问/不存在资源统一响应，413 字节限制，415 不支持/损坏媒体，422 能力或预算预检，409 admission/资源状态冲突。预算不确定与真正估计超限使用不同 code，详见预算文档。SSE 已开始后以现有 error/finish reason 契约返回，禁止再尝试改 HTTP 状态码。

## 前端所有交互细节

1. 图片选择、粘贴、拖放走同一队列。输入框普通文字粘贴不受影响，非图文件保留原上传路径。选择框 accept 仅为提示，服务端仍验证。
2. 草稿每项具有 local、uploading、ready、failed 状态；上传中禁用发送；失败项可重试/移除；其他已经就绪项不丢失。支持纯图片发送。成功前不清空输入和图片列表。
3. 上传绑定发起时的 conversationId；切换会话时取消请求或隔离迟到响应，不能把 A 的图片塞进 B。释放 object URL，处理取消后的孤儿上传资源。
4. ready 显示缩略图、文件名、尺寸、移除按钮与发送版本说明；失败显示原因。图片名称用 textContent，预览 URL 仅来自本系统，不把文件名或错误正文当 HTML。
5. 发送前刷新/使用当前模型能力，兼容模型显示“支持图片”；不兼容时给可执行提示。发送侧后端仍必须重新校验。
6. 服务端明确接受回合后才清空对应草稿；422/409/网络错误时保留或恢复草稿及 requestId。幂等重试不能再次上传、绑定或发送同一逻辑请求。被拒绝时不要留一个伪装成成功的空助手气泡。
7. 网络状态未知时按 requestId 查现有回合再恢复，不能让“恢复草稿”变成重复执行。使用另一个 Agent 已提供的入场/查询契约。
8. 历史及即时消息统一展示图片内容块顺序；预览不可用显示“图片不可用”，不能用破图替代状态。重新生成按钮处理图像不兼容时保留旧回复。
9. 模型切换后历史仍可看图，即使该模型不能分析图；显示能力和显示资源是不同权限。续聊校验本轮真正发送的历史图。
10. 提供键盘操作、按钮 aria-label、上传状态提示；移动端缩略图不撑破输入区，预览支持关闭。正在生成期间图片草稿行为与现有发送锁保持一致。

## 请求计划与模型替换边界

请求规划按固定路由解析当前及历史的媒体资源、选择请求变体、计算预算，产生一个不可变 PreparedRequest。适配器只编码该对象，不在发送时再重新缩放另一版图片。每一步重新规划整个实际输入，模型工具循环内后续请求也必须包含图像预算。

计数策略以 route/policyRevision 选择，可使用 provider 模块导出的函数。通用 planner 不包含 `if deepseek`、1024、384 或其他模型的 patch 常量。前端显示也不按模型 ID 猜能力。

首个真实实现是 DeepSeek Flash Responses。第二个实现使用离线假 Provider：不同图片预算公式、不同协议字段和不同限制；同一规范消息经它规划编码，前端与存储代码无需修改。这是模型可替换性的强制验收，不要求接第二家付费服务。

记录 modelId、实际响应 model、policyRevision、variant hash、预算估计、结果 usage 和结束原因；图片内容不进入普通日志。Provider file_id 以后可以优化传输，但必须按账户/端点分区，不能进入通用消息或当作 Token 省略依据。

## 分阶段执行与退出条件

| 阶段 | 代码任务 | 本阶段结束必须能证明 |
| --- | --- | --- |
| P0 契约对齐 | 读取并行任务的 turn、预算、恢复接口；确认三个文档；固定参考版本与限制 | 差异清单、接口映射、没有覆盖其他 Agent 的改动 |
| P1 资源与存储 | 媒体端口、解码验证、私有原图/变体、迁移、消息绑定、清理与备份 | SQLite/内存契约一致；旧库迁移；失败无半文件；引用完整 |
| P2 规划与适配 | 内容块贯穿 replay/loop；能力预检；模型媒体策略；预算与 SDK 编码 | 假模型捕获真正图片；计数与发送变体一致；不兼容零调用 |
| P3 API 与 UI | 上传预览与删除；模型能力；前端草稿和历史；错误与重试 | 浏览器完整上传、看图、刷新、重生、模型切换流程 |
| P4 集成验收 | 下方矩阵、现有检查、浏览器检查、真实端点小规模 smoke | 无真实 API 的检查全过，真实视觉证据独立报告 |
| P5 文档与交接 | 更新 ADR 026/新 ADR、README 能力范围、CHANGELOG、环境配置 | 可复现运行说明、风险、测试日志、来源和亮点证据 |

不按具体天数承诺工期。每阶段先达到退出条件再推进；真实端点不可用时保留待验收状态，不能声称多模态功能已全部完成。

所有单元/集成用例使用临时数据库与媒体目录，不读取真实用户附件。模型假适配器记录收到的内容和调用次数。以下编号写入测试名或交付报告，便于逐条核验。

### 真实端点小规模验收

仅在实施环境已有可用凭据且允许运行 smoke 时执行；密钥只读环境变量，不写报告。三项测试都保存脱敏的实际 model、usage、策略版本和请求变体摘要，不记录 Base64。没有凭据时标记 BLOCKED，不能使用假模型代替真实通过。

- S01：现场生成包含随机四位数字与大色块的 PNG，文件名和提问不包含答案。询问数字和颜色，模型应识别两者。确认线上请求具有图片内容，不是提示词泄漏。
- S02：两张现场生成的清晰图片，分别是大数字 2 与 7，按顺序询问各自内容，再交换顺序；回答对应顺序改变。记录允许结果格式，不用一句宽泛的“描述得不错”验收。
- S03：在新一轮仍引用上一张图，重启后重新生成，验证资源链路和真实响应；之后选择文本假路由验证拒绝行为。资源相同不代表每次模型文字必须逐字相同。

识别失败要区分请求未带图和模型回答错误；后者不是前端已完成的证据。S01–S03 是接线 smoke，不宣称建立了视觉能力 Bench。先运行全部离线测试再运行它们。

## 交付命令和证据

使用实施时现有 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`，新增针对媒体、预算、迁移、API 和 web harness 的有意义用例。真实 smoke 新增单独 opt-in 命令，默认测试不得调用真实模型。不要用占位脚本返回成功，也不要顺手启用全部 Docker 集成测试。

报告列出各 A/B/S 编号的 PASS/FAIL/BLOCKED、测试命令、脱敏结果和浏览器检查截图位置。截图按仓库约定归档，个人附件不放进源码。共享文件的最终差异必须解释与另一个 Agent 的衔接。

数据库备份现有脚本只覆盖 SQLite，本任务需增加包含被引用媒体的逻辑备份清单和恢复说明，校验数据库引用与文件 SHA256。不能声称“数据库备份成功”就是多模态历史可恢复。旧程序不理解新结构化列时不支持直接覆盖回滚；回滚需要恢复兼容版本与对应备份。

备份清单对应同一份数据库快照；清单中的不可变资源在复制与校验完成前持有保留标记，避免并发清理造成缺文件。恢复后逐项验证摘要，并明确报告无法恢复的资源。现有 cookie 身份是本地 handle，并非公网认证；本期只在现有本地安全范围内扩展资源授权，不声称提供多租户公网安全。

`docs/myfree/` 当前在 .gitignore 中。本文和关联设计已按本地学习目录归档；实现成果应另更新正常跟踪的 ADR/CHANGELOG。用户未要求时不要修改忽略规则、强制提交私人笔记或清理他人文件。

## 可用于面试的亮点与证据边界

| 亮点 | 可以讲的工程取舍 | 必须交付的证据 |
| --- | --- | --- |
| 能力驱动的模型替换 | 同一消息结构适配不同模型/协议，能力未知时明确拒绝 | A09、A10、A22 |
| 可重放的媒体上下文 | 原图不可变，媒体引用随消息持久化，重生不依赖浏览器缓存 | A08、A13、A20 |
| 计数与发送一致 | 预算使用实际请求变体，分开 Token 和 HTTP 字节预算 | A23、A24 与 B 系列 |
| 显式的不兼容处理 | 用户选择模型不被擅自覆盖，历史图和新图都校验 | A14–A17 |
| 可靠的前后端闭环 | 草稿、上传、入场和流式是不同状态，重试不会重复执行 | A17–A19、A26 |

这些在验收通过前只能描述为设计目标。不要把支持图片输入包装为原生视频/实时语音能力，也不要把 smoke 成功包装为通用多模态效果评测。
