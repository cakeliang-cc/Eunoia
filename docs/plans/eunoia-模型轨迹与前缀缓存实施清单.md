# Eunoia 模型轨迹与前缀缓存实施清单

日期：2026 年 11 月 8 日。执行对象：DSH。状态：**已实施并完成离线验收 A01–A32 与真实 smoke S01–S03**；结果见 [验收报告](../features/eunoia-模型轨迹与前缀缓存验收报告.md)。核对代码基线：`824d369`，SQLite schema v9 → v10。

目标：结合 DSH 的动态背景快照与 Codex 的状态基线，保存可恢复的模型轨迹。普通轮次保持历史前缀，状态变化时追加更新，压缩或切换模型时建立明确的新边界。生产实现不采用 OpenCode 方案。

本任务交付代码、迁移、测试、运行证据和更新后的介绍文档。实际完成情况以验收报告与本次提交为准；代码默认开关仍为 legacy，本部署在 `.env` 启用 durable。

| ADR 030、031 | 每请求预算、私有图片、能力预检和固定发送变体 | 让新增轨迹成为预算和图片预检的同一份输入来源 |

特别注意两处现有行为：`fitContext()` 的裁剪只影响该次 `requestInput`，下次仍从原 `input` 计算；`lastUserIndex()` 用角色识别保护区。引入持久背景消息后，必须分别处理“裁剪后历史重新出现”和“背景 user 误作真实用户回合”这两个问题。

`PROMPT_VERSION` 是内容版本标识，不是供应商缓存键。工具审计日志也不是模型回放的唯一事实来源。

## 4 必须保持的契约

### 4.1 聊天消息和模型轨迹各有职责

聊天消息继续用于 UI、搜索与导出；模型轨迹负责下一次请求的内容与顺序。两者通过 messageId、requestId、step 和稳定条目 id 关联，同一用户消息只进入模型轨迹一次。

模型轨迹覆盖：真实用户内容、应用注入的背景、每个模型步骤的输出条目、实际交回的工具结果、供应商所需的回放元数据。分步 assistant 原文不能合并成最终聊天气泡后再用作原轨迹，工具间的文本位置必须保留。

模型轨迹只重放数据，不执行任何工具。恢复工具调用的执行状态继续由 ADR 028 管理。没有观察到结果的调用仍是未知，不得自动重新执行或伪造成功结果。

### 4.2 普通轮次和新阶段

这里的“阶段”是同一会话内具有一套稳定提示词、工具声明、协议配置和活动历史的回放区间，代码可命名为 `epoch`。

- 普通轮次在同一阶段追加条目，历史内容和顺序不变。
- 压缩、有效历史回退、工具声明或提示词变化、模型/供应商/编码版本变化，建立新阶段并记录原因。
- 同一阶段内固定提示词与工具声明的完整内容和顺序，不仅保存哈希。运行时工具权限可以立即改变，执行器使用当前策略；能力声明有意变化时再开启新阶段。
- 压缩与裁剪优先保证窗口和语义正确。它们可以损失缓存复用，必须可解释、可恢复。

### 4.3 身份和权限

条目持有服务端产生的 `source`、真实回合身份和应用上下文种类。UI 发来的文本不能自行声明为应用背景。检索内容与工具返回均按数据处理，不能因来源标签或重放而升级成高权限指令。

适配器决定背景使用何种合法 wire 角色；预算保护、用户消息计数和回合边界必须依赖条目身份，不依赖 `role === 'user'`。

## 5 持久化设计

第一版建议新增独立端口，例如 `src/session/model-transcript-store.ts`，SQLite 和 InMemoryStore 同时实现。表名可适应项目命名，但以下字段语义不能省略。

| 记录 | 必需字段与用途 |
| --- | --- |
| 回放阶段 `model_epochs` | id、userId、conversationId、父阶段、原因、实际提示词、提示词版本、工具声明快照、provider/model、协议与编码版本、活动窗口引用、创建时间 |
| 不可变条目 `model_items` | id、conversationId、来源阶段、全序 seq、requestId、真实 turnId、step、kind、source、内容版本、完整 payload、内容摘要、作用域、可选 messageId/callId、完成状态 |
| 请求尝试 `model_steps` | attemptId、requestId、step、attemptNo、epochId、按序 inputItemIds、outputItemIds、请求配置摘要、阶段修订号、发送状态、responseId、usage、实际响应模型、错误/结束原因 |
| 状态基线 `model_context_state` | conversationId、epochId、key、作用域、内容摘要、渲染版本、revision、最新提交 itemId，包含显式清空状态 |

具体要求：

- 条目正文存私有数据库，图片继续引用现有媒体资产。第一版无需新增工具输出文件仓库；存模型实际收到的、已经受工具和本轮上限约束的结果，不能再按审计的 2000 字符裁剪。
- 多次请求复用不可变条目 id；每次请求保存输入 id 顺序和配置引用，不重复保存整段历史正文。不要因每轮全量复制而引入额外的历史存储增长。
- 新阶段可以引用旧条目，新阶段窗口是明确的有序视图；原始记录保留到删除/保留期清理。新阶段不能无意带回已裁剪的内容。
- seq 分配、条目幂等键、状态 revision 与活动阶段推进由存储事务保证。SQLite 唯一约束至少覆盖稳定条目幂等键及 `(requestId, step, attemptNo)`；同一消息或同一步的重试不重复追加输出。
- 请求状态区分 `prepared`、`sending`、`completed`、`incomplete`、`failed`、`unknown`。写入 prepared 只能证明本地已准备，不能证明供应商已接收；进程崩在发送中时采用 unknown。
- `model_context_state` 表示活动轨迹已经纳入的背景，不宣称模型一定读到。准备输入条目和推进该基线在同一事务完成；失败后条目仍可稳定重发，不在新回合无依据地跳过。
- schema 在执行时最新版本上递增，本次观察为 v9，不覆盖其他任务新迁移。旧库升级两次应幂等，用户和历史记录不能被重建丢失。
- 备份包含新增表；删除会话/用户清理轨迹和状态。媒体引用统计要包含仍可回放的轨迹与近期检查点，防止原聊天行回退后图片先被 GC。
- 普通日志只输出 id、数量、哈希、版本和错误类型；凭据、图片 Base64、完整背景、工具正文和 reasoning 不写入普通日志。诊断正文导出遵守既有访问控制并默认不含私密正文。

## 6 背景快照与状态更新

### 6.1 状态块分类

`buildRuntimeContext()` 上游改为产生结构化块，再由固定版本渲染器渲染。保留原文以便重放，不在恢复时重新读取当前文件生成旧文本。

| key 建议 | 范围与更新规则 |
| --- | --- |
| workspace | 持续有效状态；目录、工作区身份变化时追加完整块快照 |
| permission | 持续有效状态；策略变化立即追加，工具执行始终查真实策略 |
| skills、toolGuidelines | 持续有效说明；文本或版本变化时追加；工具 schema 变化另开阶段 |
| relationship、narrative | 持续有效背景；值变化时追加，值清空时发撤销标记 |
| clock | 时间点快照；沿用当前分钟粒度与实际时区，每个用户回合最多追加一次；分钟未变则不重复，循环内不每步刷新 |
| retrievedMemory、attachments | 本轮资料，携带 requestId；只对本轮检索/附件适用，不能把“上轮相关”解释为“本轮仍相关” |
| continuation、safetyDirective | 本轮指令，携带 requestId；仅在对应回合生效；continue 不伪装为用户原话 |
| archivedSummary | 属于阶段检查点，不作为每轮普通状态块重复附加 |

scope 是协议的一部分，必须进入模型可理解的封装。持续状态以同 key 最新版本生效；本轮资料在下一真实用户回合自动失效。相同文字的本轮资料仍可能需要再次发送，不能为去重丢失当前回合的适用性。

### 6.2 比较与渲染规则

- 固定状态块排序；对象按固定字段序序列化。哈希覆盖块 key、scope、版本、渲染器版本及规范化内容。
- 只规范化应用自产块的确定格式；assistant 原文、工具参数、工具结果和用户内容不做为了命中率的 trim、重排或重写。
- 持续块相同不追加，变化则追加该块的完整快照；删除时追加 tombstone，明确旧值失效。重新激活已删除块必须产生新 revision。
- 每条更新携带来源、key、revision 和生效回合。固定封装说明新状态覆盖同 key 旧状态；不能把权限仅留给模型自行理解。
- 在模型调用前从权威状态获取块。目录被工具修改后，如果工具结果已给出新目录，也应按统一状态通道更新基线；不得直到下一用户回合仍宣称旧目录。
- 若正在运行的回合允许外部撤权，在下一工具调用前按真实策略拒绝，并在下一模型步骤告知变化；若当前产品只在回合开始快照权限，要维持该约束并明确告知，不能声称支持即时撤权。

## 7 模型调用与提交顺序

按每个模型步骤执行以下顺序：

1. 确认会话准入仍有效，取得当前阶段、真实 turn 和活动轨迹。
2. 解析当前和历史图片能力/资产，生成固定媒体计划；不支持或能力未知时在写入新模型轨迹与调用前明确失败，维持现有媒体预检语义。
3. 读取当前背景状态，生成必要更新；组装逻辑输入及本轮已有结果。
4. 计算实际请求预算。发生裁剪时先创建新的活动视图与边界；用裁剪后的图片集合重新规划，直到预算、内容引用和发送字节一致。
5. 在事务中保存新条目、prepared 请求引用及状态基线；校验阶段 revision，过期计划重新构建。失败则本次模型调用和后续新工具执行都不发生。
6. 适配器按固定版本编码。捕获实际请求正文的可比较投影：提示词、工具、消息内容及顺序、影响协议的设置。排除凭据与请求追踪 id，图片使用字节摘要等价表示。
7. 标记 sending 后发送。流式内容照常展示；终态输出按供应商返回顺序原样映射为持久条目。不要同时回填 delta 拼接版和终态版，造成重复助手文本。
8. 若输出含工具调用，必须先可靠保存其调用事实及回放数据，再按原有权限和顺序执行。返回结果可靠保存后，才允许发送下一次模型步骤。
9. 完成每步 usage 与状态结算，再继续循环；聊天气泡仍按现有 UX 汇总，但不反向覆盖模型轨迹。

本期无需主动向用户提供完整请求正文抓取。最终 wire 比较通过 mock SDK/HTTP transport 在测试中完成，线下真实诊断只保存必要摘要。

### 写入失败的处理

现有审计记录器允许失败后继续，这是它的已有用途；新增可回放轨迹的持久化失败必须有独立语义。不能可靠记录准备输入时，不发模型；不能可靠记录调用时，不开始该工具；工具已经执行但结果保存失败时，保留当前可见文本并终止后续步骤，由 ADR 028 对账。不得伪装为可恢复的成功回合。

错误应提供稳定 code，例如 `MODEL_TRANSCRIPT_UNAVAILABLE`，不把新的恢复问题悄悄转成“切回旧模式继续执行”。失败不抹掉已展示文本或已产生的副作用。

## 8 恢复与边界规则

### 8.1 重启和发送状态不确定

从数据库恢复相同活动阶段、条目顺序、背景基线、媒体摘要和已完成工具结果；比较新环境状态后才追加变化。不能因进程重启而重建一份不同的旧背景。

`sending` 请求没有可靠终态时转为 unknown，不把它当作 completed。已有完整结果则正常回放；未知工具按 ADR 028 展示未知并由人决定下一步，模型回放不能自动发起同一副作用。

无法配对的工具调用不得直接发送给供应商。第一版在恢复新阶段用有来源的中断说明代替未闭合调用，保留调用参数和执行事实供诊断，说明“结果未知，未自动重跑”；这会改变前缀，必须记录原因。不得写成“工具失败”或“没有执行”。

### 8.2 停止与继续

完整终态条目按原文保存。只有流式半截文本、没有完整供应商输出时，保存 incomplete 状态及实际展示的文本；不要伪造 reasoning 签名或完整 tool_call。继续时建立必要的恢复边界，保留半截文本并追加本轮 continuation。

若安全缓冲最终替换了内部生成的回答，后续会话采用对用户实际生效的安全答复和状态建立新阶段。不能把被丢弃的内部答案重新送回 UI 或恢复为普通助手历史。

### 8.3 重新生成和历史回退

保持当前仅能重新生成最新且未被摘要覆盖回复的限制。回退整轮模型轨迹，包括该轮 assistant、工具调用与结果、背景更新和步骤记录的活动引用；原始审计可保留。用户内容只保留一次。

重新生成不会回滚已经发生的文件修改或命令。使用现有恢复事实提示该轮有过工具执行；新的工具动作仍是新的决定。媒体预检、准入失败和阶段写入失败不能先破坏旧活动回复。UI 消息回退与模型活动视图推进必须事务性一致。

### 8.4 旧会话首次启用

旧库没有完整轨迹时，以现有摘要和 user/assistant/图片内容创建一次标记为 `legacy-seed` 的基线。其覆盖边界与消息 id 固定，不能每轮重新导入、不能从 2000 字符审计片段虚构完整工具输出。升级后第一次输入允许建立新缓存，文档如实标记旧轨迹不完整。

### 8.5 关闭功能和回滚

采用服务端启动配置 `MODEL_TRANSCRIPT_MODE=legacy|durable`，迁移完成但默认 legacy，离线与 smoke 验收后再启用 durable。配置不由客户端逐请求控制。

legacy 保留当前聊天行为；durable 会话有明确阶段标记。重新开启 durable 时，若检测到 legacy 期间新增聊天记录，必须建立新的 seed 阶段，不能跳过这些消息。开关只控制代码路径，不做破坏性降级迁移。应用二进制回滚使用与数据库 schema 兼容的版本或独立备份。

## 9 压缩与每请求预算

所有输入来源统一进入预算：提示词、工具声明、背景、用户内容、assistant、reasoning、工具结果、图片，以及输出预留和安全余量。缓存命中内容仍占上下文窗口，不能从预算中减掉 cachedTokens。

- 保护区按真实 turnId/条目来源计算；背景 wire 角色不能移动保护区。
- 摘要以完整已闭合回合/工具组为单位。进行中的回合和未配对调用不得进入普通摘要压缩。
- 原摘要模板偏长期陪伴，本次新增面向编码轨迹的检查点结构：当前目标、约束、已完成与证据、变更文件、工具执行结果、未知结果、未完成与下一步、仍需引用的媒体。不要假装文字摘要看过图片内容。
- 建议新阶段顺序：固定指令/工具 → 摘要 → 保留的近期闭合轨迹 → 最新权威状态快照 → 当前用户内容及本轮资料。历史回合资料只作为历史；最新快照位于旧状态之后，避免旧更新重新覆盖它。
- 若权威状态仍超限，明确 budget_exhausted，不静默删掉权限或把图片当零 Token。
- `fitContext()` 发生工具结果压缩或旧条目删除时，提交新的活动窗口修订/阶段边界。下一步与重启沿用该视图，原始工具结果保留但不自动重新进入活动输入。
- 图片预算基于最终视图中的出现次数与固定发送变体；同一 asset 多次出现仍按多次计入。重新规划不可改变既有变体字节，变体或编码策略变更应有显式边界。
- 摘要生成保留现有端口，新增轨迹输入契约；第一版允许独立摘要调用，单独计量费用。复用父会话提示词/工具前缀的摘要优化可后续做，不能先承诺摘要调用享有主会话缓存。
- 空闲压缩也遵守会话互斥；对过期阶段 revision 生成的摘要不能覆盖正在追加的新轨迹。

## 10 模型替换与供应商适配

新增回放契约由适配器声明，至少包含：协议/encoderRevision、动态上下文合法承载方式、工具历史编码、reasoning 回放要求、缓存字段方式。未知能力不能通过模型名字猜测。

同一阶段冻结实际协议表示。换模型、换供应商或协议/提示词/工具声明改变时开启新阶段，从可移植语义内容重新投影；不把其他供应商的 reasoning 签名、responseId、file_id 或不透明检查点当作通用消息。

第一版不依赖 `previous_response_id` 或其他远端会话作为唯一历史来源。支持的 reasoning 按适配器要求保存；不能合法跨边界回放的元数据丢弃或替换时记录边界与原因，不能构造假的签名。必须依赖不透明项且无合法替代时返回明确不兼容错误。

延续 ADR 031：新模型不支持活动轨迹里的图片时，返回现有 `MODEL_INPUT_UNSUPPORTED` 或 `MODEL_CAPABILITY_UNKNOWN`，scope=history；不自动换模型、不静默删图。未注册的供应商能力用离线假适配器验证，不能声称已支持第二家真实服务。

检查 `cachedResolver` 等模型对象缓存，键应覆盖 provider 实例/路由、model 与编码配置；不能因先前进程级缓存而把另一供应商请求发到旧端点。

## 11 计量与前后端兼容

### 11.1 usage

每个模型请求尝试单独保存实际 inputTokens、outputTokens、totalTokens、cachedTokens、响应模型和供应商可提供的 cache-write 字段。缺字段为 null，不能改成 0。若 SDK 已把未知转换为 0，在更早边界保留字段存在性或增加测量状态。

定义三个不同口径：

- `lastRequestUsage`：最后一次请求计量，兼容现有聊天完成帧 `usage` 的含义。
- `turnUsage`：本轮每次请求已知 usage 的求和，包含重试尝试；提供 measuredSteps、totalSteps 和 incomplete 标记。
- `contextTokens`：最近一次实际请求的本地窗口估计，不做累计费用指标。

不要把部分请求已知的费用当完整账单。缺失 cache 明细时不输出伪精确命中率/未命中费；费率按 provider、实际模型、时段和版本外部提供，未配置则只报 Token。图片局部估计不能再加到供应商 inputTokens 中。

### 11.2 前后端

- chat、regenerate、continue 和 requestId 幂等语义保持；增加可选诊断字段，旧客户端可忽略。重放已完成请求不调用模型，不重复追加轨迹或费用。
- 新的轨迹错误有稳定 code 和可读中文，UI 不把持久化失败展示成“已完成”。保留已经显示的半截文本，重试沿用现有 requestId 规则；新执行使用新 requestId。
- 页面刷新仍显示原有消息、图片与工具摘要；内部背景和 reasoning 原项不变成用户气泡、模型调试文本不泄露到普通 UI。
- 本期不增加用户需要理解的 epoch、cache key、状态版本配置，也不要求用户人工观察统计。导出报告由脚本完成。

## 14 真实对照和上线条件

### 14.1 运行边界

新增独立实验脚本，默认 dry-run，无真实调用；必须显式 `--live` 才使用环境凭据。不得覆盖已有实验 JSON，结果路径带 runId。

真实对照默认上限：总计 24 次模型请求尝试（含工具轮次、重试及摘要请求），供应商 usage 累计最多 200,000 输入 Token，每次输出最多 2048 Token；按每次已知 usage 和下一次保守估计检查余量。将允许的计量波动写入结果，超限即停止后续请求。未知 usage 时停止继续花费，不能按 0 继续。预算为本地停止条件，不宣称远端账单有绝对硬上限。

只用合成数据与临时工作区。工具使用真实循环加本地确定工具，禁止在真实用户仓库做写入。并列比较 legacy 与 durable，交换先后顺序，给每组独立前缀标记；真实 assistant 逐字回填，两组语义任务与输出长度相近。缓存无法强制清空，不宣称严格冷缓存。

| ID | 必测场景 | 交付证据与通过标准 |
| --- | --- | --- |
| S01 | 真实 DeepSeek 路由的长回复对照 | 经项目实际适配器；至少两轮；报告每请求 usage、回复长度、历史助手数量、结构检查和两组执行顺序；费用计算可离线复核 |
| S02 | 真实模型的一次工具往返后继续下一用户轮 | 临时工具结果含标记；请求捕获证明完整结果与顺序；工具执行次数与调用决定一致；回放本身零工具执行 |
| S03 | 同一配置重启后的继续与一次状态改变 | 同阶段内容摘要稳定；变更块有新增记录；原工具不被重跑；真实模型若无法连通则待验收，不能由 mock 替代 |

现有 16 请求实验累计输入费用减少 32.07%，是特定合成长回复样本，不能作为硬性通过门槛。上线条件是离线契约全部通过、真实路由合法、窗口与任务结果正确，且真实报告没有无法解释的费用回退。若净收益不成立，保留新功能关闭，提交原因分析而不是提高命中率后宣告成功。

比对必须同时给出输入长度、命中与未命中 Token、输入费用、输出费用、包含摘要的总费用、首字延迟，以及状态/任务结果；未知项明确标记。只提高命中百分比不算净收益。
