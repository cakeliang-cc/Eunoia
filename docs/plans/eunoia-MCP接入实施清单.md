日期：2026 年 11 月 8 日。执行者：DSH。状态：待实施。目标是一次交付完整、可管理、可恢复的 MCP 接入能力，统一验收后交付，不拆成只读版、HTTP 版或后续补齐版。

本清单允许重构工具契约、权限层、媒体结果及运行生命周期。执行前读取当前 HEAD：模型轨迹与前缀缓存正在并行修改，不能覆盖其接口，也不能仅凭文件存在宣称已验收。项目仍按本地部署的安全边界设计，不额外宣称具备公网多租户认证。

> 按本清单实现 Eunoia 的完整 MCP Host 接入：stdio 与 Streamable HTTP、匿名/Bearer/OAuth 认证、工具发现和更新、读写权限及交互审批、资源与模板、提示词模板、补充信息交互、异步任务、结构化和图片结果、前后端管理及持久化恢复。重构现有 ToolDefinition/ToolRegistry 和权限端口，使内置工具与 MCP 工具走统一执行管线。完成 M01–M60 离线/本机集成验收及 L01–L06 端到端验收，再交付代码、迁移、使用说明和证据。禁止将关键能力改写为 TODO 或未来版本；不得以“工具列表可见”代替可执行、可取消和可恢复的完整链路。

这里“完整”指以下能力矩阵全部达到约定，不等于盲目声明支持所有历史或第三方扩展。已弃用的 sampling 不启用；未知协议、未知扩展和当前模型不支持的媒体必须明确报告，不能静默成功。

## 3 学习 DSH 与 Codex 的哪些机制

DSH 把 MCP 连接做成插件，将发现的工具转换为普通工具定义，以服务名隔离命名，管理连接代次、重连和撤销。Eunoia 采用这种桥接方式，接入自己的 registry 和生命周期，不引入 Cordis。[DSH 工具桥接](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/mcp/mcp-client/src/tools.ts)，[连接监督](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/mcp/mcp-client/src/connection.ts)。

Codex 的官方配置覆盖 stdio/HTTP、认证、工具筛选、超时和工具审批；源码将 MCP schema 转为内部工具并在实际调用处应用审批。Eunoia 借鉴配置、执行身份及审批绑定的思路，不把外部工具直接当成本地只读函数。[官方配置](https://developers.openai.com/codex/mcp/)，[schema 适配](https://github.com/openai/codex/blob/748ab55ca7de0b647d9a7a9d9a8e70e00f28666d/codex-rs/tools/src/mcp_tool.rs)，[调用与审批](https://github.com/openai/codex/blob/748ab55ca7de0b647d9a7a9d9a8e70e00f28666d/codex-rs/core/src/mcp_tool_call.rs)。

协议参考固定到 `2026-07-28`，向旧版本兼容交给 SDK，最终报告列出实际测试版本。当前 lockfile 已含 SDK 引入的 `@modelcontextprotocol/client` 2.1.0，但应用没有 MCP 接入；实现时改为显式直接依赖并核对实际 Node/SDK 兼容性。

## 4 架构与重构落点

```text
模型供应商适配器
       ↓ tool calls
原生 Agent loop
       ↓
统一 ToolRuntime：参数校验 → 权限 → 执行 → 结果 → 预算/记录
       ├─ 内置文件/命令/技能工具 → 现有 Gateway 与沙箱
       └─ MCP 工具适配器 → McpClientManager
                              ├─ Streamable HTTP
                              └─ stdio ProcessTransport

Web/API → McpService / InteractionBroker / CredentialStore
                        ↓
SQLite / 私有媒体库 / 模型轨迹 / 审计
```

模块名可以随当前项目调整，但职责分离必须成立：

| 模块建议 | 职责 |
| --- | --- |
| `src/mcp/types.ts`、`config.ts`、`store.ts` | 服务配置、作用域、能力、错误和持久化契约 |
| `client-manager.ts`、`catalog.ts` | 连接代次、认证身份、目录快照、重连、关闭 |
| `transport/http.ts`、`transport/stdio.ts` | 使用 SDK 的协议/传输，封装受控网络与进程流 |
| `tool-adapter.ts`、`content.ts` | 工具定义、schema 验证、结构化结果与媒体导入 |
| `resources.ts`、`prompts.ts`、`tasks.ts` | 标准操作、缓存/订阅、模板、任务句柄 |
| `auth/*`、`credentials.ts` | OAuth 生命周期、密钥存储与短期凭据租约 |
| `src/service/mcp.ts`、交互 broker | 应用编排、授权、暂停/恢复、API 和 UI 数据 |
| `src/tools/*`、`src/agent/*` | 统一工具契约、循环、预算、模型和轨迹适配 |
| `web/*`、`src/api/*` | 管理页、来源展示、审批、用户交互和 SSE |

MCP SDK 类型不扩散到模型供应商、会话和前端。不要在 loop 中用工具名称前缀堆协议分支；不要另造一个绕过现有 loop 的 MCP 执行循环。

### 4.1 统一工具契约

当前 ToolDefinition 将参数固定为 Zod，registry 从 Zod 导出 JSON Schema，loop 直接 `safeParse()`。重构为统一 `ToolContract`：对模型声明的 schema 与运行前的 validator 成对保存；内置工具通过 Zod 工厂生成，MCP 工具通过原始 JSON Schema 工厂生成。

必须保留 nested object、required、enum、array、union、数值/字符串约束以及合法本地引用。选用支持声明 draft 的验证器，禁止自动远程下载 `$ref`；不支持的 schema 有明确诊断，不能用 `z.any()`、删除约束或只取 properties 冒充等价适配。模型供应商需要的 schema 降级必须由其适配器完成，运行前始终按原契约验证。

工具定义新增可信来源：builtin 或 mcp；MCP 包含 serverId、原始工具名、catalogRevision、contractHash、执行身份和策略分类。原始名称与模型名称双向映射持久、确定，支持模型名称长度/字符限制，截短要加摘要防碰撞。

readOnlyHint、destructiveHint 和幂等提示作为远端元数据保存；实际权限和并发分类由应用可信策略决定，不由远端自我授权。

### 4.2 统一结果契约

将只有 output 字符串的结果扩展为有序内容块、可选 structuredContent、失败类型、远端身份与执行状态；保留稳定文本投影供旧工具和旧客户端使用。内部结构只有一份权威内容，不能让文本投影与内容块各自修改。

扩展模型输入和适配器的工具结果表示：支持工具结果里的图片，或以有来源的关联上下文承载图片；选择必须固定、可恢复、保持块顺序及 callId 配对。不能把 MCP 图伪装成用户上传内容，也不能仅返回图片文件名。

## 5 配置和作用域

### 5.1 配置模型

至少包含：id、名称、owner、可见会话/项目范围、enabled、required、transport、endpoint 或进程配置、认证引用、超时、结果限制、工具筛选与策略、配置 revision。

- 同一 serverId 是应用分配的稳定身份，不以远端自报 serverInfo.name 充当唯一键。
- HTTP 支持 URL 和引用环境变量/私密库的 header；凭据值不出现在普通配置响应中。
- stdio 支持 executable、args 数组、cwd、显式 env 引用、运行环境与固定镜像/程序标识。argv 默认不经过 shell 解释。
- 启动配置、导入文件与 GUI 使用同一 schema 和校验器。支持导入常见 `mcpServers` JSON，导入先预览、解析环境变量引用并确认；不执行文件里的 JS/YAML 可执行标签。
- 用户可设置工具允许/禁止列表，deny 优先；每会话可选择启用的服务。配置改动先验证再原子保存，失败保留原配置。
- required 服务不可用时，对依赖它的会话明确报错；optional 服务失败可用其它工具，但 UI 不得显示为可用。

### 5.2 身份与隔离

连接/目录/资源缓存至少按 owner、serverId、endpoint/configRevision、认证身份与授权 scope 隔离。OAuth access token 刷新可沿用同一身份；更换账户或 scope 必须使相关授权和目录重新验证。

API 按现有本地部署要求校验 Host、Origin 与控制面 token；跨用户/会话访问统一拒绝。OAuth 回调使用自己的单次状态校验，不依赖前端提供 ownerId。模型无权修改服务地址、启动命令、凭据或工具策略。

### 5.3 默认限制

所有限制可在部署配置中明确调整并做启动校验：启动 15 秒、普通调用 60 秒、关闭宽限 5 秒；每个服务最多 100 个已启用工具、单个 schema 64 KiB、全部已启用 schema 合计 512 KiB；单次结果最大 32 MiB、文本投影默认最多 20,000 字符。媒体还需通过现有解码/像素/单图/总量限制。

限制覆盖分页累加、UTF-8 字节、压缩后解码大小和流式接收，不能只在完整 JSON 已进入内存后检查。超限不静默随机删工具；返回可操作的诊断，允许用户缩小工具选择。长任务有独立 deadline 和轮询间隔，不套用普通 60 秒超时。

## 6 传输与连接生命周期

### 6.1 stdio

实现 `ProcessTransport`/`DuplexProcess` 端口：stdin、stdout、stderr、退出状态、关闭、取消、进程身份和字节上限。当前 ContainerCli 忽略 stdin、只支持有界命令结果，不能直接用于 MCP；需要扩展 OCI runtime 的受控交互进程能力，例如执行 `docker exec -i`，同时保持既有 baseline 校验。

提供沙箱进程和受信宿主进程两种实现。默认沙箱启动，镜像用固定 digest、限制挂载/网络/资源；缺少所需隔离时明确失败。宿主模式仅能由部署明确允许并在配置中显示信任范围，模型或普通会话审批不能打开该模式。不得把宿主模式标成“已经沙箱隔离”。

父进程环境使用允许列表，不全量继承服务端环境；应用 API key、数据库凭据和控制面 token 不自动传入。服务器需要的 secret 经显式引用和用途授权提供；沙箱仍遵守 CredentialBroker 的授权、有效期与撤销策略。应用对调用的许可不能缩小远端 token 本身的权限；部署禁止长期凭据进容器时，必须采用可签发的短期凭据或受控认证代理，不能悄悄注入长期宿主 token。

stdout 仅用于协议，stderr 有界脱敏记录。停止服务、删除配置或应用退出时先正常关闭，宽限后终止进程树，释放容器 exec 会话及句柄。没有配置级授权时不自动下载/安装 npx 包；安装和更新是显式管理操作，显示来源及版本。

### 6.2 Streamable HTTP

使用官方 SDK 实现协议、内容类型、事件流、版本兼容及取消；应用提供受控 fetch/网络策略。HTTPS 默认，HTTP 仅显式允许的本地/私网服务；请求、重定向、认证元数据和 URL 交互都需要校验目标，跨域不转发原 Authorization。

地址来自用户批准的配置，不从模型参数或工具返回任意替换。对私网/环回/元数据服务的访问按部署允许规则处理；允许合法本地 MCP 服务的配置，同时阻止非预期目标和 DNS/重定向绕过。

关闭会取消已有任务所属请求，释放事件流与 socket；不能误关另一会话仍在使用的共享连接。协议本身是否长连接/有状态由协商版本决定，不将旧会话语义写死。

### 6.3 连接代次与重连

状态至少包括 disabled、connecting、ready、auth_required、reconnecting、failed、closing；状态保存最近错误 code、时间、工具数和下一次重试时间，不保存凭据正文。

连接/发现失败采用有上限的指数退避。传输重连不等于重放 tools/call：已经发出的写操作、未知副作用不得自动重试。旧代次退出后，其迟到回包和目录更新不得覆盖新代次。连接重建可以重新发现工具，但不能伪造先前调用结果。

## 7 工具目录与缓存稳定性

分页读取全部目录，检查重复名称、循环 cursor、schema 大小与有效性、支持的能力及工具选择。构建不可变 catalog 快照后整体发布；发现失败保留上一有效快照并标记失效原因，不能把半份目录暴露给模型。

每次回合持有目录快照和执行映射；不能只固定 schema 却在调用时通过同名工具转发到新的服务/账户/参数契约。工具名称、schema、description、指令和策略有摘要及 revision，权限审批引用该身份。

目录更新先形成待应用 revision，在安全模型步骤边界更新；与当前模型轨迹的 tools-change 阶段衔接。当前快照内工具被撤销时立即拒绝新的执行，不为保缓存继续使用已撤销权限。连接临时断开不等于删掉当前历史里的工具声明。

支持 tools/resources/prompts 更新事件与 SDK 支持的订阅机制；无通知的服务可手动刷新。目录保持确定顺序，schema、服务说明和描述全部计入模型预算。工具过多时通过选择/筛选与明确预算诊断解决，不能先花钱调用模型才发现窗口不足。

## 8 权限与人工交互

### 8.1 权限决策统一

把与具体文件路径无关的工具授权和审批从沙箱专用编排中抽成可复用端口，保留现有沙箱执行策略。MCP 只读服务可以在没有本地 workspace 时工作；不通过伪造 workspace/executor 获得权限。

MCP 操作按外部读取、外部写入、未知副作用分类。未分类默认需要审批；远端 annotations 不能直接成为放行依据。明确配置的信任策略可授权确定工具，写操作必须经过当前策略允许或具体人工授权。

一次授权绑定 owner、conversation、server/endpoint、账户/scope、工具原名和 contractHash、参数摘要、策略版本及 TTL。描述/schema 改变、账户切换、删除/禁用服务或撤权时重新检查。审批前不调用远端，不因模型回答“已获同意”自行批准。

### 8.2 暂停与恢复

引入持久 `InteractionBroker`，统一人工审批与服务器补充信息交互的状态机，但区分两者授权含义。必须做到“等待中能刷新、能拒绝、能取消、能恢复”，不把 APPROVAL_REQUIRED 当普通工具失败交给模型反复重试。

等待项记录准确的 pending action、回合/调用/账户/配置版本、过期时间和恢复凭据引用。审批完成后重新校验身份、策略和版本；旧批准不能授权已经改变参数或账户的动作。重复点击只产生一次有效恢复。

允许按现有应用结构实现独立运行任务或持久暂停/显式 resume，但不得用“重新让模型生成工具调用”代替恢复原动作。SSE 断开不丢失待处理项；取消生成会取消对应等待，取消后迟到批准不执行工具。会话不因遗留 waiting 状态永久锁死，恢复与会话准入保持一致。

### 8.3 elicitation

支持表单和 URL 两种模式；现代多轮结果与旧版嵌套请求通过协议适配层统一。UI 展示服务身份、请求原因和准确字段，提供接受、拒绝、取消与超时；表单回答需本人预览修改并按请求 schema 校验。

表单不能收集密码、API key、访问令牌等秘密；URL 模式显示目标域名，由用户明确打开，不能后台自动导航。完成 URL 交互只按协议或可信完成信号恢复，不能把“打开过网页”当授权完成。

对同一动作的用户输入补交按 SDK 语义发送，可能产生新 RPC id，但仍关联原始应用 actionId，不能重复产生外部写操作。补充信息不构成工具权限提升。

## 9 认证与密钥

认证模式与服务 revision 绑定：匿名、Bearer/env header、OAuth。认证失败在 UI 显示 needs login/expired/insufficient scope 等可读状态，不自动删掉工具历史或假装无权限服务调用成功。

OAuth 使用官方 SDK/成熟库实现资源与授权服务器发现、预注册客户端、CIMD、兼容 DCR 注册、PKCE、回调验证、刷新及注销；应用必须补充 owner/服务绑定、一次性状态、过期处理、刷新 single-flight 与 UI 状态。三种注册路径用可控授权服务器分别验证，按协商能力选择，不把任一可用路径写成后续工作。

回调固定并校验来源和预期 issuer，code 不跨服务兑换。授权新增 scope 需要用户看到变化；刷新仅更新同一认证身份，不能暗中切换账户。401 后可按协议刷新凭据，但是否重发原工具调用必须按“是否已被接受执行”和幂等保证判定，不能普遍自动重试写工具。

新增 `McpCredentialStore`，secret/token/refresh token 使用认证加密保存，建议 AES-256-GCM，AAD 绑定 owner/server/credential id 与版本。主密钥来自部署环境或系统密钥库，不和 SQLite 备份一起保存。未配置可用加密存储时，不接受需要持久化的秘密，不回退明文存储。

管理 API 对秘密采用只写值、读回占位与重新输入/清除操作；真实值不进入工具 schema、聊天、URL query、进程 argv、日志和普通导出。运行期凭据租约复用现有授权/脱敏能力；HTTP OAuth 与沙箱 broker 的职责分开，不能为迁就短期 broker 丢失完整 OAuth 刷新语义。

远端也可能回显凭据。将当前已知 secret 登记到脱敏器，检查错误、说明、结果和 stderr，在入模、显示及普通轨迹持久化前处理。schema 的 const/default 等约束出现秘密时拒绝该定义，不能为脱敏而悄悄改掉校验语义；需要保留的原始敏感响应只能进入单独加密诊断存储，不能回放给模型。

## 10 结果、资源和提示词

### 10.1 工具结果

- text 按原块顺序保留；structuredContent 独立保存并按 outputSchema 校验，必要时生成有界文本投影。
- `isError`、协议错误、网络错误、超时、取消和未知执行状态分别记录。远端业务失败不是成功的空字符串。
- 图片从实际返回字节导入私有媒体库，解码验证并绑定 owner/conversation/action；保留来源与顺序，按实际变体进入下一模型步骤。
- 资源链接仅作为链接展示，访问时走明确资源/网络操作；禁止把远端 file:// URI 解释成本机文件。
- 嵌入资源保存内容类型和来源，文本/图片可按能力使用，其他二进制保存为私有引用并给出可见说明；音频/视频仅在对应模型与编码能力存在时入模，否则明确未发送，不宣称模型已读取。
- 结果超限有 truncation/省略范围/原始大小记录；审计片段、模型实际文本投影与完整私有记录分开。模型轨迹保存实际发送结果，后续回放不重新向服务器查询生成旧结果。

为非图片二进制增加受访问控制的通用私有 artifact 记录，复用已有 blob 存储设施，绑定 MIME、字节摘要、owner/conversation/action、引用和配额；不要用假图片宽高塞进现有 ImageAsset。下载、GC、删除及备份同时覆盖该类资源，禁止将其自动当代码执行。

### 10.2 资源与模板

支持分页资源列表、模板列表、模板参数补全、读取、用户选择入上下文、订阅与退订。仅访问当前用户可见且已启用服务的 URI/模板。URI 来自资源条目或已验证模板，绝不作为宿主任意路径。

资源缓存按账户/scope、server/config revision、URI 与权限分区，遵守 SDK 支持的 TTL/失效信息；更新通知标记旧内容过期，在下一安全步骤重新获取。已经进入模型历史的旧内容保留原快照，不能被通知就地改写。

### 10.3 提示词模板与服务器说明

支持列表、参数补全、获取和多模态预览。用户确认后作为带来源的本轮任务模板/背景使用，不能按服务返回角色插入伪造历史助手结果或替换固定系统提示词。加载模板不执行其中提到的工具。

服务器 instructions 作为有来源、有版本、有大小限制的外部使用说明处理；不能改变权限、要求泄露凭据或覆盖应用规则。只对可见服务作用域注入，变化在上下文/工具阶段边界处理。

## 11 长任务与恢复

支持协商后的 Tasks 扩展。工具调用返回任务句柄时，保存 server、账户、原 action/call、远端 taskId、TTL、轮询建议与本地 deadline；按间隔轮询并可订阅通知。最终结果通过统一结果管线处理；input_required 交给 InteractionBroker。

用户可查看进度、取消和待补充输入。取消请求被确认只说明取消意图已送达；未核实远端终态前不能宣称动作已撤销。进程重启先按原身份查任务状态，不重新执行创建任务的工具。过期、查不到、账户丢失时明确记录未知/不可恢复。

普通 tools/call 在发送后断线且无结果，也视为未知；恢复不重发写操作。读操作是否自动重试由可信策略声明，不能只依据远端 idempotentHint 推断。

远端任务可以有自己的长时间工作，但 Eunoia 不引入自动跨任务规划；任务结果什么时候重新进入模型，需要受回合准入和显式继续动作约束。模型历史重放、审批重放、任务轮询均不能额外执行原始副作用。

## 12 媒体预算与模型替换

工具返回图片意味着媒体集合可能在循环中增长。将“整回合固定一份 media plan”重构为“每次模型步骤生成不可变发送计划”，复用已绑定资产变体和策略；预算、实际编码、请求体大小和轨迹捕获都使用同一份计划。

完整预算包括内置/MCP schema、工具说明、服务器 instructions、资源/模板、所有媒体出现次数、文本、reasoning、历史工具结果及输出预留。缓存命中不能抵扣窗口；本地图片估算不能再加到真实 inputTokens。

模型不支持图片/工具或能力未知时明确报告当前/历史/工具结果的作用域，不自动换模型、不静默丢图。用户可明确选择另一兼容模型继续同一已记录结果；不得为了重新拿图再执行 MCP 写操作。

结果编码通过 ModelTurn/ProviderAdapter 扩展，不在 MCP 客户端中写死 DeepSeek 或某个 SDK 的字段。离线第二适配器必须使用不同工具结果媒体编码，证明核心/存储/UI 不依赖模型名。

## 13 存储、回放与数据生命周期

复用当前 SQLite 和存储端口，新增结构至少覆盖：

| 实体 | 关键内容 |
| --- | --- |
| 服务配置/绑定 | owner、范围、endpoint/进程、认证引用、策略、configRevision、启用状态 |
| 目录快照 | 服务/身份、revision、原工具与模型名称映射、schema/描述摘要、能力、抓取/失效时间 |
| 调用与尝试 | actionId、requestId、turn/call/step、server、目录租约、参数/结果引用、进度、已发送状态及未知结论 |
| 待交互记录 | approval/elicitation、owner、原动作、schema/URL、有效期、响应、幂等恢复键 |
| OAuth/secret | 密文、密钥版本、认证绑定、过期/撤销元数据；非秘密配置仅引用 id |
| 远端任务/资源绑定 | task 句柄、状态与 TTL；资源快照、订阅范围；媒体资产和轨迹引用 |

动作准备与发送状态可靠持久化，不能沿用“审计失败可忽略”来假装有完整恢复。重要写入失败时不开始新的远端副作用；已发送但结果写入失败按未知对账，不自动重发。

模型轨迹保存工具契约/来源 revision、调用参数及实际发送结果，回放读取本地快照，不要求旧 MCP 服务仍在线。目录变化和认证范围变化与已有 epoch/工具变化边界衔接，避免另造一套前缀状态。

删除服务：先停用并撤销新执行，处理/取消待交互与远端任务，再关闭受管进程、流与凭据；历史调用仍可审计到服务墓碑，但不再有可用认证。删除会话/用户和保留期清理覆盖新增实体与媒体引用。备份包含恢复所需记录及媒体，但不包含解密主密钥；恢复时认证缺失必须显示待重新登录。

## 14 API 与前端闭环

以下路由可随现有风格合并，但行为不能缺失。新增控制面按项目规则验证来源与访问权限，不提供任意 URL fetch 或任意宿主 spawn API。

| API 操作 | 必须覆盖的行为 |
| --- | --- |
| `/api/mcp/servers` 及 `/:id` | 列表/新建/读取/修改/删除；带 configRevision 乐观锁，秘密不读回 |
| `/:id/connect`、disconnect、refresh | 明确启停/重连/刷新目录，幂等；状态可查询并流式更新 |
| `/:id/tools`、tool-policy | 工具来源、启用/禁用、读写分类、审批策略和当前可用性 |
| `/:id/auth/*` | 登录、回调、认证状态、退出与凭据替换；回调单次绑定 |
| `/:id/resources/*`、prompts/* | 分页、模板补全、读取/预览、订阅；原 URI/模板名放结构化 body，避免路径编码歧义 |
| `/api/mcp/interactions/:id` | 查询、接受、拒绝、取消与幂等恢复；越权/过期/旧 revision 不执行 |
| `/api/mcp/tasks/:id` | 本地句柄查询、继续查看、取消；不能猜远端 taskId 访问其他账户 |
| 会话 MCP 绑定 | 持久保存选中的服务器；回合中变更按安全边界生效 |

UI 在设置区提供 MCP 服务管理、配置预览、运输方式和运行位置、认证、状态、工具清单与筛选。聊天工具卡明确区分内置工具与“服务名 · 工具名”，展示进行中、等待批准、等待输入、远端任务、失败和未知结果。

表单、URL 交互与批准卡必须刷新后仍可读、键盘可操作，支持重复点击去重与过期态；URL 不自动打开。上传图片、草稿、停止/继续和重生的已有流程不能退化。390px 窄屏和桌面都要验收，无横向溢出；外部描述/HTML/URL 使用现有转义与链接策略，防止脚本注入。

前端不显示 protocol revision、catalog lease、encoderRevision 等实现细节；需要用户做决定时展示服务、账户、目标、参数摘要与影响。

## 15 故障、错误和计量

统一错误至少区分：配置/能力不支持、认证缺失/过期/scope不足、schema无效、目录过期、权限拒绝/等待批准、交互取消/过期、连接失败、超时、远端业务失败、结果/媒体超限、未知副作用和关键持久化失败。

本地动作状态与远端执行结论分开保存：本地可为 prepared、waiting_approval、sending、waiting_input、running_task、finished；执行结论为 succeeded、failed、cancelled 或 unknown（对应已有 UNKNOWN 语义）。本地超时/取消后，远端仍可能执行；没有终态证据时结论仍为 unknown，不能用“停止等待”推导“副作用没发生”。pending、进度或部分文本不能被 `ok=true` 汇总成任务成功。

日志记录 actionId、serverId、身份引用、catalog/config revision、耗时、状态、结果大小与裁剪信息，不记录 secret、原始 Authorization、Base64 或未脱敏的完整参数正文。私有轨迹仍按自己的访问控制保存实际模型内容。

复用逐模型请求 usage 口径，另记录 MCP 延迟、调用次数、字节、重连和等待时长；不能把 MCP 调用次数当 Token，也不能把网络开销算成模型输入费用。取消、等待和未知不是“任务成功”。

## 17 验收方法

测试使用可控的真正 MCP fixture server，而不只 mock `callTool()`。分别提供 stdio、HTTP、OAuth、目录更新、图片、资源/模板、elicitation 与 Tasks 行为；使用随机运行标记证明调用发生在服务器端。涉及最终模型请求的检查捕获真实编码后的 transport body。

每个 M 编号映射到测试名与报告证据。需要实际容器/浏览器的条目标明环境并实际运行；不能用跳过或 mock 结果宣称全部验收完成。

| M30 | elicitation 索要秘密、危险URL、未确认URL | 不通过普通表单收秘密；不后台导航；显示服务和目标域名 |
| M31 | 现代 input_required 与旧版嵌套交互 | 协议适配后应用状态一致；恢复不重复创建原始副作用 |
| M32 | 文本多块+structuredContent+outputSchema | 顺序与结构保留；校验失败不冒充成功；旧文本投影稳定 |
| M33 | isError、协议错、网络错、timeout、abort | 错误类型可分；模型和UI可见；无成功空结果 |
| M34 | tools/call发送后服务执行成功但连接断开 | 结果未知；恢复/重连不自动重发写动作；调用次数保持一次 |
| M35 | 一次模型回合混合内置读取与 MCP 调用 | 都经统一调度/策略/事件流；工具名、参数、callId和结果配对正确 |
| M36 | MCP返回两图穿插文本，随后模型读取 | 字节真正导入媒体库并入模，顺序与来源正确，无伪用户上传 |
| M37 | MCP图损坏/超限/不支持格式、结果包含音频 | 明确诊断/记录，不伪造看图/听音；无解码资源泄漏 |
| M38 | 图片在本轮第二步才出现、同图多次、计划后编码 | 每步计划与实际字节一致；按出现次数计数；body和Token预算分别生效 |
| M39 | 切到文本模型，活动历史含 MCP 图片结果 | 明确能力错误；无静默删图/自动换模/重新执行原工具 |
| M40 | 资源列表/模板分页、补全、读取、选入上下文 | 正确URI与服务；无跨账户缓存；用户选择后才注入对应快照 |
| M41 | resource file://、链接到内部HTTP、未知外部URI | 不读取宿主文件、不隐式fetch；按服务资源与网络策略处理 |
| M42 | 资源订阅更新、退订、重连、用户权限减少 | 失效/重读正确；旧历史不就地改写；不可见数据不再获取 |
| M43 | prompts列表、参数补全、获取、多模态预览和确认 | 仅显式应用；角色/正文不覆写系统权限或伪造过去消息 |
| M44 | description/instructions/prompt/结果含注入与HTML | 有来源、按数据处理、UI转义；不能改权限/读secret/自动执行 |
| M45 | Tasks扩展创建、轮询、通知、最终结构化/图片结果 | 句柄持久；按间隔执行；结果回到同一action和统一媒体管线 |
| M46 | Tasks需要补充输入、重复补交、取消但远端继续 | 输入去重；仅终态确认后结算；取消意图不伪装回滚 |
| M47 | 任务运行时服务重启/应用重启/句柄过期/认证丢失 | 查原任务或报未知；不再次创建任务；状态和UI可解释 |
| M48 | 正文/媒体/目录/说明超过大小限制，流式持续灌入 | 接收与解析有界，及时取消；报告具体限制；其它回合仍可用 |
| M49 | schema/资源/说明增长，模型窗口接近上限 | 请求前统一预算；必要时有明确裁剪/阶段边界或拒绝，不静默丢工具 |
| M50 | 重启后回放完整 MCP 结果，远端服务器已关闭 | 读取本地快照，零远端工具调用；图片引用与配对保持 |
| M51 | 重新生成/继续、请求幂等重放、并发同会话 | 沿用当前契约；不会因读历史重复副作用；旧服务调用身份可追踪 |
| M52 | 关键调用/结果存储失败 | 新副作用不开始；已发送动作保留未知事实，不自动重发 |
| M53 | 删除服务/会话/用户、GC、备份/恢复 | 凭据/等待/任务/流与媒体引用按规则处理；无悬挂可用授权 |
| M54 | 管理页新增两种传输、编辑失败、刷新、认证和启停 | 状态闭环；输入不丢；秘密不读回；服务不可用不显示ready |
| M55 | 聊天内工具来源、审批、补充输入、任务进度 | 清楚区分内置/MCP、进行/等待/失败/未知；取消与重试语义正确 |
| M56 | 390px/桌面、键盘、恶意服务名称/说明/URI | 无横向溢出，关键操作可用，无HTML执行或未确认跳转 |
| M57 | 不同模型编码/媒体预算的两个适配器 | 不改MCP/存储/UI即可切换；未知能力明确处理，协议字段不泄漏核心 |
| M58 | 诊断、错误、SSE、导出、数据库与进程参数扫描诱饵秘密 | 非私密控制面无secret/Base64；密文存储与日志脱敏有证据 |
| M59 | 相同MCP调用跨重试、轮询和模型多步骤的计量 | 每次网络尝试/工具动作/模型usage分别记账，不重复算Token或误记任务成功 |
| M60 | 全仓回归、旧配置、内置工具和图片流程 | 类型/lint/测试/build/browser均通过；已有能力不退化，无关键TODO |

## 19 端到端验收与交付标准

| ID | 验收场景 | 必须提供的证据 |
| --- | --- | --- |
| L01 | 真正stdio进程和真正容器stdio进程，经Web发起模型工具调用 | fixture服务随机标记、模型请求捕获、工具结果、运行位置与进程退出证据 |
| L02 | 真正HTTP MCP服务，远端读与带批准的写 | 完整服务日志、审批前计数0/批准后1、工具来源UI与结果 |
| L03 | 真正受控OAuth授权服务器+MCP资源服务器+浏览器 | 首次登录、回调、scope、刷新、拒绝/退出、重启后凭据恢复的端到端记录 |
| L04 | resources/prompts/elicitation/Tasks综合服务 | 用户预览应用、表单/URL批准、任务状态、取消/重启及媒体结果全过程 |
| L05 | 公共文档MCP与当前真实模型的一次检索/阅读往返 | 官方服务地址、实际发现工具名、模型发出的参数、真实结果和usage；不使用写外部业务数据的账号 |
| L06 | 用户配置的GitHub/浏览器或同等服务，完成“查问题→内置改代码→测试→审批外部写” | 临时仓库或可控服务、前后端截图、调用/轨迹/权限证据；若无外部账号，用真实协议的本机服务证明完整闭环并明确实际接线范围 |

受控fixture必须是真实子进程/HTTP/OAuth/浏览器交互，不以函数mock替代。M01–M60 与 L01–L04 为无付费账号即可执行的完整功能验收；L05需要当前实际模型与公共网络。L06的第三方账号不可用时，只能报告对应服务未接线，不能声称所有第三方已兼容。

外部写入验收只使用用户明确指定并授权的测试目标；默认用可控服务，不在真实业务仓库创建Issue/PR或发送消息。

真实模型 smoke 的工具列表和任务轮次有上限：默认最多12次模型请求、累计200,000已报告输入Token、每次输出最多2048；请求前结合保守估计检查余量，usage未知则停止继续调用。上限控制本地后续请求，不承诺远端账单绝对上限。重跑须使用独立runId且保留旧证据。

验收报告逐项列 PASS/FAIL/BLOCKED 与证据；条件不足不能将 BLOCKED 改成 PASS。所有本次承诺的产品能力仍须完成代码和本机集成验收，不得因缺少某家账号而删掉实现。

## 20 检查命令与交付清单

实现时新增明确的 MCP 集成脚本，启动受控服务并自动清理；具体命令写入报告，不能只提供“手动点一下”。既有检查至少运行：

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run browser:check
```

在具备容器的环境执行真实stdio沙箱/取消/清理测试；真实模型单独显式开启，默认测试不消耗真实API。测试报告保存提交与配置revision、SDK/协议版本、命令、通过/失败/跳过数、必要截图和脱敏日志。

- [ ] 单一交付包含本清单全部能力，无“基础版已完成，其余后续”的结论。
- [ ] 新ADR说明工具/权限/媒体/生命周期重构和完整兼容矩阵；与当前模型轨迹改动协调。
- [ ] M01–M60、L01–L06逐项有真实证据及正确状态；全仓回归完成。
- [ ] `docs/mcp/` 提供配置、认证、日常使用、故障恢复与卸载清理说明；README/CHANGELOG更新。
- [ ] 增加 `.env.example` 的必要引用配置，不提交秘密；导入/导出与备份恢复有说明。
- [ ] 默认无外部服务，但用户配置后完整闭环可用，不需要修改代码逐个接服务。
- [ ] 更新项目亮点/简历：仅将已通过验收的MCP能力写成成果，不声称所有外部服务天然安全或已认证兼容。
