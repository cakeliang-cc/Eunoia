# Eunoia 开发工具补齐实施清单

状态：待 DSH 实施与验收。日期：2026-11-08。

本次完整交付八组能力：持续进程与预览、浏览器操作、本地图片读取、联网搜索与网页读取、用户提问、代码语义、多文件补丁、按轮次撤销。前后端、权限、预算、安装配置和故障恢复均属于交付范围。

背景与选型见[开发工具现状与选型](../research/tools/eunoia-开发工具现状与选型.md)。本文的工作分解不代表分期上线；不以仅注册工具、只完成后端或只运行替身测试作为最终完成。

## 1 与现有工作的关系

实施前阅读最新代码以及 [MCP 清单](./eunoia-MCP接入实施清单.md)、[Subagent 与 Team 清单](./eunoia-Subagent与AgentTeam实施清单.md)、[模型轨迹清单](./eunoia-模型轨迹与前缀缓存实施清单.md)、[多模态设计](../design/eunoia-多模态接口设计.md)。当前另有 Agent 开发 MCP 和 Team，应基于已集成、已提交的对应基线创建独立 `feat/developer-toolkit` 分支，保留工作区其他人的改动，不把未确认的修改混入提交。

复用现有工具契约、ModelTurn、轨迹、回合幂等、沙箱、MCP、Team、图片资源与权限服务。允许必要重构，但每项能力只有一套领域服务；模型工具与 Web API 都调用它。原有 read/write/edit/bash 保持可用。

现有工作不能代替本次交付：

- MCP Host 解决连接，浏览器 MCP 服务仍需实际安装、配置和运行。
- Web 工作台终端不自动成为 Agent 可以查询的后台作业。
- 用户上传图片不自动使 Agent 能查看工作区图片。
- Team 任务板不等于通用用户提问；需求答案也不是工具权限批准。
- 底层 checkpoint 恢复不等于按轮次精确撤销。

长任务检查点和第二个真实模型厂商的接入验证继续按各自设计推进；本次确保新增工具遵循现有模型端口和上下文边界，不重复建设这两项。

## 2 工具归属和完成范围

| 能力 | 实现归属 | 必须交付的可用后端 |
| --- | --- | --- |
| 进程和预览 | 原生领域服务与工具 | 受控容器进程、日志与预览路由 |
| 浏览器 | MCP 执行，内部管理生命周期和媒体 | 锁定版本的 Playwright MCP 与 Chromium 环境 |
| 本地图片 | 原生 read_image | 文件网关读取，既有媒体管线入库与编码 |
| 网页读取 | 原生 web_fetch 与可替换 FetchProvider | 有网络策略和正文提取的 HTTP 后端 |
| 联网搜索 | 原生 web_search 与可替换 SearchProvider | Tavily HTTP 适配器；凭据独立配置 |
| 用户提问 | 原生工具、持久交互服务和 UI | 主 Agent 提问，子成员经主 Agent 汇总 |
| 代码语义 | 原生工具和 LSP 适配层 | 实际 TypeScript/JavaScript 语言服务 |
| 补丁和撤销 | 原生文件领域服务和 UI | 复用工作区与 Team 集成 journal |

工具名称以下文为建议，可按项目命名调整；必须提供实际名称、schema、权限类别、错误码、超时和取消语义的目录。浏览器工具沿用 MCP 发现结果，不再注册一套同义原生浏览器工具。

GitHub Issue/PR、设计平台、错误监控、数据库、PDF/Office 文档等属于按需服务配置，不作为本次八组能力的隐藏必需项。本次不增加一套专门包装所有 git 或 npm 命令的工具。

## 3 共用执行和资源模型

- [ ] 每次调用带 owner、conversation、turn、toolCallId；Team 内另带 run、member、activation、taskAttempt、generation。服务器绑定身份，模型不能用参数冒充他人。
- [ ] 进程、浏览器、LSP、预览、问题、修改集均有稳定 ID、归属、状态、版本和清理策略。状态及事件持久化，内存和 SQLite 实现共用契约测试。
- [ ] 生命周期动作有幂等键，重复创建/回答/补丁/撤销不产生第二份副作用；同键异参返回冲突。重启按证据对账，不根据数据库 running 状态自动重发命令或网页提交。
- [ ] 工具结果进入统一内容块管线。原始大日志、图片字节和差异保存在受控资源中，模型默认收到有界结果与可继续读取的引用。
- [ ] 权限取用户、部署、根运行、成员与任务的交集。注册工具不等于获得网络、路径或账号授权；MCP 工具同样经过策略、审批和审计。
- [ ] 所有下一步请求重新做上下文、图片和请求体预算；搜索/浏览器服务若产生独立费用或额外模型调用，单独记录，不能混成免费工具。
- [ ] 短工具超时、长作业寿命、模型请求取消和浏览器动作取消分别定义。浏览器已经点击或外部动作已经发送时，取消不能宣称回滚。
- [ ] 日志脱敏；事件和资源读取校验 owner。私有结果不通过猜测路径、全局缓存或公共 URL 跨会话泄露。

建议模块边界：`processes/`、`previews/`、`browser/`、`web/`、`interactions/`、`language/`、`changes/`。允许合并目录，不能将实现集中到 agent loop 的工具名分支。

## 4 持续进程和预览服务

### 4.1 模型工具

提供 `process_start/status/read/wait/input/stop/list`。启动参数包括受控 cwd、command/argv、可选 PTY 和时限；环境只能来自允许的变量和凭据句柄，不能传整个服务器环境。已有一次性 bash 保留其无跨调用 shell 状态的语义。

- [ ] start 尽快返回进程句柄和初始状态，不等到开发服务器退出才返回。
- [ ] 状态区分 starting、running、exited、stopping、stopped、unknown，保存退出码、开始/结束时间和资源归属。
- [ ] stdout/stderr 分流，支持日志游标、分页和截断标识；滚动日志丢失返回明确缺口，不假装完整。输出洪泛不耗尽内存/数据库。
- [ ] input 只有 PTY/可输入进程支持，校验长度、归属和状态；发送成功不代表子程序处理成功。敏感输入不回显到审计或模型历史。
- [ ] wait 是可取消等待，不占模型 HTTP 请求许可；超时返回仍在运行，不能把等待超时变成作业失败。
- [ ] stop 先定向终止进程组，再按宽限升级，核对后代已结束；不能使用宽泛 pkill 或为停止一个作业杀掉仍被其他作业使用的整容器。
- [ ] OCI 运行时增加受控长期进程端口；复用 MCP 正在建设的双向子进程基础，禁止另开可绕过权限的 host exec。
- [ ] 宿主/容器重启后核对实际进程身份、创建标记和 generation，防止 PID 复用；不能恢复控制的记录转 unknown，不自动补启动。
- [ ] 服务退出、Team 停止、成员关闭和显式结束都有清理规则。用户可以将已授权预览保留到配置的 TTL，浏览器连接断开不终止预览。

### 4.2 预览

提供 `preview_start/status/stop`，由服务组合进程和受控路由，而不是让模型自行猜容器 IP。

- [ ] 启动指定项目命令，管理端口分配与冲突；只有配置/批准的容器端口可发布，不开放任意网络代理。
- [ ] 服务就绪有超时和状态证据；可配置 HTTP 探测，同时保留进程退出与错误日志。页面返回 200 不等于前端行为验证通过。
- [ ] 返回分别供用户和浏览器后端访问的地址。浏览器在容器或独立进程时，不能把它自己的 localhost 当成项目服务。
- [ ] 预览路由绑定 owner/run/workspace，按受控 origin 转发 HTTP 和开发服务需要的 WebSocket；鉴权不向被预览应用泄露主服务凭据。
- [ ] 对 HTML、脚本、Cookie、下载、iframe 和 WebSocket 明确隔离策略；预览内容不能以主应用 origin 读取 Eunoia 私有 API、Cookie 或本地控制 token。
- [ ] UI 显示就绪状态、日志、打开预览和停止入口。端口已被其他用户/成员占用时不得连接到错误服务。

默认每成员最多 3 个长期作业、每运行最多 2 个预览；日志、空闲寿命和保留期可配置。模型不能自行提高限额。

## 5 浏览器 MCP 和视觉验证

采用 Playwright MCP，版本由实施时验证并锁定；不在生产启动配置里依赖浮动 latest。内部 BrowserSession 绑定 owner、run/member、workspace、MCP 连接实例、profile 和 generation。

### 5.1 安装和运行

- [ ] 提供可复现的 `tools:setup`、`tools:doctor` 或等效项目命令，检查 Node、MCP 服务入口、浏览器二进制、容器网络、媒体和模型能力。
- [ ] 安装/修复是用户或运维显式操作；模型普通调用不自动下载安装包、运行任意安装脚本或升级版本。
- [ ] 状态至少区分未安装、环境不符、已安装未启用、连接中、可用、鉴权失败、断开。不能只提供一个 enabled 布尔值。
- [ ] 首次配置默认隔离 profile；不同成员/运行不共用 Cookie、tab 和可写下载目录。MCP 实例缓存键包含归属和配置 revision，不因相同 serverName 串用连接。
- [ ] 使用现有浏览器的 attach 模式需明确选择并有独占/冲突提示；默认不接管个人浏览器或继承登录状态。模式切换记录新会话，不能在模型参数里随意换 CDP 地址。
- [ ] 工具能力以实际服务清单为准：导航、页面结构、点击、输入、选择、等待、tab、viewport、截图、控制台和网络观察均要验证；缺必需工具则 doctor 不通过。

### 5.2 调用与结果

- [ ] 同一浏览器上下文内的变更动作顺序执行；别的成员不能操作其 tab。页面刷新后的旧元素引用返回失效提示，不自动点同名元素。
- [ ] 浏览器能访问授权预览；公网访问遵守网络策略，不能利用导航、重定向、子资源、WebSocket 或脚本访问未授权宿主/内网。仅校验 navigate 参数不足以完成隔离。
- [ ] 收集页面控制台 error、失败请求及必要的 HTTP 错误，脱敏 Cookie/Authorization 和敏感查询参数；返回时间、页面和关联动作。
- [ ] 截图保存为不可变媒体资源，经正常 image 内容块进入下一次模型请求；只返回文件路径或 UI 缩略图不算完成。
- [ ] 支持桌面与 390px 窄屏、视口/整页/元素截图；记录 viewport、DPR、范围、原图与发送变体。过长截图按媒体限制拒绝或显式分段，不能隐蔽裁剪后声称看过整页。
- [ ] 有 DOM/可访问性结构不代表已经做视觉检查。模型不支持图片时，可执行结构检查，但视觉验证状态必须是未执行，并提示选择合适模型。
- [ ] 页面内容作为外部数据，不升级为系统指令。文件上传/下载通过授权工作区与资源句柄，不接收服务器任意绝对路径。
- [ ] 页面观察、截图、表单提交和账号操作按实际效果分别分类，不能只相信服务端 readOnlyHint。工具截图写入内部媒体库不额外扩大工作区写权限；提交表单等动作仍受原有授权范围约束。
- [ ] 停止操作核对服务及浏览器资源；已送达的点击/表单提交保持真实结果或 unknown，不自动重复。历史记录恢复不承诺恢复 Cookie 和 tab 句柄。

上游参考：[Playwright MCP](https://github.com/microsoft/playwright-mcp)。本次无需同时实现 Chrome DevTools MCP 或 Stagehand 原生后端，配置与服务边界保留替换能力。

## 6 读取本地图片

增加原生 `read_image({file_path})`，通过文件网关获取授权字节，再进入 MediaService；不得绕过沙箱路径规则直接在宿主 readFile。

- [ ] 支持既有 JPEG/PNG/WebP；依据真实解码格式、像素与字节限制校验。SVG、GIF、PDF 等不在本次新增支持范围，返回明确格式错误。
- [ ] 读取时核对路径、符号链接、敏感文件和文件变化；以实际读取到的字节建立不可变资源，后续文件变化不修改历史图片。
- [ ] 标记来源为 tool，保存原图/派生变体及哈希；正文只放图片引用与必要元数据，不能把 base64 当普通文本塞进上下文。
- [ ] 模型能力为 unsupported/unknown 时，在读取和入模的合适边界拒绝视觉调用，不能返回“看到了图片”。
- [ ] 复用现有图片 Token 与请求体双预算，按实际发送变体核算；读多张或重复发送按每次请求实际图片计数。
- [ ] 子成员访问图片需要有效资源授权，不能放宽全局 conversationId 检查。UI 能展开本次工具图片及来源文件。

本地图片内容一旦返回工具结果，就按既有轨迹规则持久化；重新生成、压缩和跨模型恢复保持原图身份与能力边界。

## 7 网页读取和联网搜索

### 7.1 契约和真实后端

提供 `web_search({queries, domains?, timeRange?})`、`web_fetch({url, cursor?})`。稳定工具契约不携带某个主模型的名称；后端选择由服务配置决定。

- [ ] FetchProvider 交付 HTTP 实现，HTML 转正文/Markdown，文本按编码解码；二进制、PDF 和需登录页面返回类型/鉴权说明，不伪装成功正文。
- [ ] SearchProvider 交付 Tavily HTTP 适配器，支持认证、超时、错误映射和来源规范化；凭据使用已有加密存储或环境句柄，不能拼入 URL 或模型历史。
- [ ] Tavily 使用基础搜索和有限结果，默认关闭额外生成答案、原始全文及图片；避免引入隐形模型调用。其他服务可实现同一 Provider，不需要改 agent loop。
- [ ] 未配置搜索凭据时 UI/doctor 标记不可用，调用返回结构化错误；不使用空数组或伪造搜索结果替代真实后端。搜索与网页读取可分别启停。
- [ ] 搜索结果包含标题、URL、摘要、可获得的日期、查询与来源；缺失日期保留 unknown，不能编造。网页结果保存最终 URL、抓取时间、状态、截断与内容引用。
- [ ] 来源 ID/链接随消息历史保留，UI 展示引用，最终回答可使用真实来源链接；搜索摘要不自动当成已读取全文。

Tavily 的 API 参考：[官方搜索接口](https://docs.tavily.com/documentation/api-reference/endpoint/search)。不要求用户更换当前主模型，也不能假设主模型密钥可用于搜索账号。

### 7.2 网络与内容控制

- [ ] 公网 fetch 只接受 HTTP/HTTPS，拒绝含凭据 URL；按部署策略处理协议降级。校验 DNS 和实际连接目标，覆盖 IPv4/IPv6、映射地址、重绑定及每次重定向。
- [ ] 默认拒绝 loopback、私网、云元数据和宿主管理地址；授权预览使用独立的受限预览通道，不能因此为普通 fetch 放开整个内网。
- [ ] 网络限制在实际发起请求的一侧执行；使用代理时代理同样落实策略。不能只检验字符串主机名。
- [ ] 限制并发、重定向、时长、压缩前后字节、解码与转换工作量；建议 30 秒、最多 5 次跳转、解压后 5 MiB，每次模型可见正文最多 50,000 字符。
- [ ] 不自动携带用户 Cookie、主模型密钥或任意自定义认证头。跨 origin 重定向不转发敏感头。
- [ ] 返回内容带外部来源，不执行脚本，不把网页中的指令作为系统指令；分页读取定位同一不可变抓取结果，网页变化不偷换历史。
- [ ] 429/鉴权/超时分别返回可处理错误；有限重试尊重服务规则并记录实际请求数。搜索费用与模型 Token 分开统计，未知费用不显示为零。

## 8 结构化用户提问

提供 `ask_user_question`，支持有稳定 ID 的问题、单选/多选/自由文本、推荐选项和 blocking/timed 模式。默认只允许根 Agent 直接向用户发起；子成员把问题提交给主 Agent，避免多人同时弹窗。

- [ ] 仅在缺少必要信息或需要真实用户决策时提问；已有授权、已回答问题和常规可逆实现选择不重复确认。可独立完成的工作继续推进，不把工具能力变成每步弹窗。
- [ ] 问题有 owner、conversation/run、调用、来源成员、generation、schemaHash、状态和事件；回答必须指向问题 ID 及版本。
- [ ] blocking 等待明确回答或取消；timed 等待结束后仍可回答，模型只能继续不依赖答案的工作。超时、关闭窗口、预选项和空回答都不是授权或默认选择。
- [ ] Web 卡片支持选择、编辑、自定义答案、提交、取消；最多 3 个简短问题一组，必要时允许纯文本，表单具有可访问标签。
- [ ] 回答接口校验 owner、选项、长度和状态，同回答幂等；旧 generation、关闭运行和已失效问题拒绝回答。问题卡刷新后可恢复。
- [ ] 回答进入原调用的合法消息边界并关联问题；不能通过普通第二轮聊天绕过当前回合互斥，也不能注入两次。
- [ ] 停止运行取消对应等待和问题；客户端断开不自动选择答案。等待期间不占模型请求许可。
- [ ] 需求问题与安全审批分开。回答“采用方案 A”不能赋予命令、路径、网络或 MCP 写权限；需要凭据时进入已有认证流程，不让模型问题卡索取密钥。
- [ ] 普通聊天与 Team 都能使用同一服务；与 MCP elicitation 共享可复用交互设施，但保留来源、协议语义和授权边界。

参考：[DSH 用户提问](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/interaction/tool-ask-user/README.md)。

## 9 代码语义工具

提供 `code_definition/references/symbols/diagnostics`。交付 TypeScript/JavaScript 的真实 LSP 后端及 LanguageProvider 端口，其他语言明确显示未配置，不宣称通用语义理解已完成。

- [ ] 采用并锁定兼容的 `typescript-language-server` 与 TypeScript 组合；记录实际语言服务和项目编译器版本，不随宿主全局安装漂移。[项目说明](https://github.com/typescript-language-server/typescript-language-server)
- [ ] 管理初始化、能力协商、workspace root、文档打开/变更/关闭、诊断版本及重启；语言服务与调用成员工作区一致，不共用另一成员的可写项目状态。
- [ ] 模型工具使用明确的 1-based 行列契约，适配 LSP 协商的位置编码；中文、emoji、CRLF 的转换须测试，不能假定字节偏移等于字符位置。
- [ ] 结果有路径、范围、版本、位置链接和分页；跨文件引用不能超出授权根。未就绪/不支持/零结果分别展示。
- [ ] 诊断结果绑定文件版本和请求目标；旧结果标记 stale，不能在修改后继续显示为当前“零错误”。
- [ ] 语言服务文件访问、子进程、项目插件加载和网络受沙箱与配置控制。服务端请求 applyEdit/executeCommand 等变更能力默认拒绝，不借只读语义查询执行修改。
- [ ] LSP 崩溃、取消、协议帧错误、输出过大均有界处理；重连后重建当前文档状态。类型检查命令仍可用，语义诊断不等于整个项目测试通过。

## 10 多文件补丁和按轮次撤销

### 10.1 变更服务

原生 `apply_patch` 支持文本文件新增、更新、删除和移动，提供 dry-run、预期版本、幂等键和修改集 ID。可选严格 diff 或结构化 operations 作为唯一公开格式，文档与 schema 必须一致，不能靠模糊字符串猜补丁意图。

- [ ] 应用前验证全部路径、权限、基线哈希、文件类型、目标冲突和资源限制；任何预检失败都不写文件。
- [ ] 对变更路径统一加锁，提交时再次核对版本；多文件写入使用 journal 和原子单文件替换，故障时返回准确已应用集合，不能声称跨文件天然全局原子。
- [ ] 每项保存 before/after 内容哈希及必要字节、权限位、增删改移动关系、来源 turn/工具/成员。二进制 patch 明确不支持，不损坏原文件；已有受控写入产生的二进制资源可由撤销日志按字节恢复。
- [ ] write/edit、apply_patch、Team 向源目录应用修改共用变更记录与冲突规则；不是只给新 patch 工具加 journal。
- [ ] 基础文本编辑保持兼容；发现文件已变化时返回冲突，不能为了补丁通过而模糊匹配到别处。

### 10.2 用户撤销

UI 提供“撤销本轮”和指定修改集撤销。接口按版本及当前状态生成预览，再执行反向变更；默认不向模型暴露可任意撤销其他轮次的工具。

- [ ] 新增文件的撤销只在当前仍匹配本轮 after 哈希时删除；用户后来改过则冲突，不删文件。
- [ ] 已修改文件只有仍匹配 after 状态才恢复 before；删除/移动恢复时检查目标位置与权限，不覆盖用户后来新建文件。
- [ ] 撤销多个相关修改集必须按依赖逆序；存在后续依赖时显示影响范围，不能用旧快照覆盖整个工作区。
- [ ] 撤销是新的可追溯变更，具有幂等键和 journal；撤销中途崩溃能对账。历史模型轨迹和原执行记录不改写为“从未发生”。
- [ ] 沙箱命令的任意写入、用户同时编辑和外部 MCP 副作用不能仅靠文件快照准确归因。命令优先在隔离工作区运行，选定产物向源目录应用时纳入 journal；直接 bind 命令产生的未归因变化明确显示不在自动撤销覆盖内。
- [ ] 外部提交、发消息、数据库写入等不能归入通用文件撤销；显示实际效果与对应服务的补偿入口。
- [ ] UI 展示本轮受控变更、未覆盖变化、冲突路径和差异，可选择取消或解决冲突后重算；撤销不修改用户 Git 提交历史，不执行 reset --hard 或 clean。

## 12 实施与迁移要求

1. 确认集成基线，新增 ADR/工具目录，列出现有执行入口的复用和必要重构；选定依赖版本并锁定。
2. 扩展受控进程、预览路由、资源归属与持久模型；统一 MCP/LSP 所需双向进程底座。
3. 完成八组工具、后端和 API，接入轨迹、权限、预算、Team 和媒体。
4. 完成全部 UI、迁移、doctor/setup、恢复与资源清理流程。
5. 运行下面的契约、真实环境和端到端验收，编写报告，再构建与部署验证。

以上属于同一次完整交付。不要将权限、UI、错误处理、冲突或恢复留作所谓下一版。数据库迁移覆盖旧会话，备份包括被引用的图片、日志和 before/after 资源；清理不能删除仍可撤销或待对账的内容。

建议默认限额：单次最多 3 个搜索查询、每次 5 个来源；单批补丁最多 100 个文件与 2 MiB 文本；诊断/引用分页最多 100 项。所有限额可由部署调整并在工具 schema/UI 说明，不可由模型自行抬高。沿用现有更严格限制时以严格值为准。
