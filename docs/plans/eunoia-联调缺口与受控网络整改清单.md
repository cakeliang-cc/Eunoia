## 3 沙箱应当具有按任务授权的网络能力

当前已有 `none/proxy_only` 配置、域名/端口策略及出口代理，见 `src/sandbox/config.ts`、`src/sandbox/network/`、`docs/sandbox/OPERATIONS.md`。出口网络、代理部署和真实绕过测试仍需落实。

Docker 的 `network:none` 只提供容器内回环网络，适合离线任务；开发服务器即使在容器内返回 200，外部浏览器也不会因此可达。[Docker none 网络](https://docs.docker.com/engine/network/drivers/none/)

将网络需求分成三条独立通道：

| 通道 | 需求 | 约束 |
| --- | --- | --- |
| 沙箱出站 | 安装依赖、访问指定 API | 经出口代理，域名/端口授权，限制实际连接目标 |
| 预览入站 | 用户和浏览器访问沙箱开发服务器 | 有归属的端口租约、HTTP/WebSocket 网关、独立预览 origin |
| 浏览器出站 | 访问已授权预览与网页 | 浏览器自己的网络隔离和策略，不能靠项目沙箱的 none 代管 |

模型服务、搜索连接器等宿主受控服务有自己的网络配置。Tavily 缺凭据不由沙箱联网解决；浏览器在宿主运行也不受项目容器的 none 自动约束。

### 推荐实现路线

保留真正离线的 none 档位，增加前端开发用的 `dev_preview` 组合配置：预览开启，公网出站默认为拒绝或显式 proxy_only。底层采用按工作区隔离的内部网络与受控网关，避免所有成员放进一个可互访的 bridge。

1. 沙箱接入自己的内部网络；网关仅代理已登记的预览目标及已授权出口，不提供任意 URL/端口转发。Docker 控制端仍属于应用控制面，不把 Docker socket 挂进项目或浏览器容器。
2. 出口网关是批准的唯一外联路径，不启用通用路由/NAT；限制直连 TCP、UDP/DNS、IPv6、宿主网关和元数据访问。代理环境变量只是客户端配置，不能作为防绕过边界。
3. 预览租约绑定 owner/run/member/workspace/container/port/generation，应用通过租约创建路由；服务监听容器内合适接口，探测、租约和实际进程相互对应。
4. 用户地址与浏览器可达地址分开返回；macOS Docker Desktop 不假设宿主能直接访问容器 IP。网关需要明确的容器/宿主连接方式，并在目标平台验证。
5. 本机网关监听仅限 loopback；远程部署使用鉴权入口。若使用端口发布，必须显式指定绑定地址，不能不加限制地把开发服务器发布到所有网卡。
6. 浏览器使用独立受控运行环境，仅能访问授予它的预览和网站；Cookie/profile 隔离与网络隔离分别验证。不同成员不能访问对方项目端口、CDP 或调试服务。
7. 在已授权部署配置内自动分配租约并执行，模型不能修改网络上限。域名变更走现有权限流程，不为每次普通页面访问重复确认。

Docker 普通 bridge 默认允许网络内互访并提供外部网络访问；`--internal` 可以限制外部访问，但不替代成员、宿主和网关的完整隔离测试。[Bridge 行为](https://docs.docker.com/engine/network/drivers/bridge/)、[内部网络选项](https://docs.docker.com/reference/cli/docker/network/create/)、[端口发布](https://docs.docker.com/engine/network/port-publishing/)

### 预览页面的应用边界

- 使用预览专用 origin，按运行隔离存储；主应用 Cookie 不透传给预览，不使用主站同源 `/preview/...` 直接运行不可信脚本。
- Cookie 的 host/domain、主服务 CORS/CSRF、iframe sandbox、postMessage 来源与目标分别处理；只换路径或只讨论同源策略不足以完成会话隔离。
- HTTP 与 HMR WebSocket 都校验租约与归属，停止/重启后旧地址和旧 generation 失效。保留可审计的打开、连接与停止状态。
- 验收应包含预览脚本尝试读取主应用资源、跨运行资源、宿主服务和 Cookie 的负向测试，而不只检查截图能否打开。

参考：[同源策略](https://developer.mozilla.org/en-US/docs/Web/Security/Same-origin_policy)、[Cookie 作用域](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies)。

## 4 截图入媒体与环境修复

浏览器已生成 PNG、MCP 已连接、UI 显示文件链接，都不等于模型收到图片。

- 优先让浏览器服务返回标准 MCP image 内容；若所选版本只返回文件引用，实现浏览器专用结果适配器，以明确工具结果字段和输出目录映射导入，不对任意 MCP 文本中的路径自动读取。
- 输出目录/卷绑定具体浏览器实例和成员，校验实际路径、符号链接、文件类型、字节/像素与读取时一致性；远程服务路径不能误当宿主路径。
- 经已有 `importToolImage` / MediaService 生成不可变 asset，保留动作、页面、尺寸、范围和哈希。记录图片进入下一次请求的编码证据，并核对真实模型回答。
- 每次含图请求重新规划预算，不能把 base64 当普通文本 Token。图片不支持时明确显示视觉验证未执行，不静默变成“已看过”。
- EPERM 先记录实际运行用户、缓存/profile 的 realpath、文件属主与执行层拒绝原因；为运行用户配置专用可写缓存/profile，安装和运行使用同一配置。若是代理执行沙箱拒绝，按其授权机制解决，不能靠 chmod 假装修复。
- Playwright、浏览器二进制、MCP 版本保持匹配；使用 `PLAYWRIGHT_BROWSERS_PATH` 等明确路径或已验证的 executablePath，不修改整个用户目录权限。[浏览器安装与缓存](https://playwright.dev/docs/browsers#managing-browser-binaries)

## 5 图片能力和第二 Provider 的核对

集成代码中的 `src/agent/request-plan.ts` 会根据 profile 的 image 能力在本地返回 `MODEL_INPUT_UNSUPPORTED`。这是 Harness 预检，不能作为真实端点不支持图片的直接证据。

当前模型目录声明 Flash 图像路由，历史多模态报告也记录过该路由的真实 S01–S03。因此先核对部署提交、会话选择的 modelId、实际 provider/endpoint、能力 revision、图片预算策略和测试请求投影；记录错误发生在发请求之前还是厂商响应之后。旧报告也不能代替本次实际验证。

正确能力配置确认后，以合成图片运行小额真实 smoke；确实没有可用视觉路由时再配置独立视觉 Provider。不能直接将 unsupported 改成 supported 绕过检查，也不能假装文本描述等同真实看图。

T06 的模型可替换测试可先用两组确定性 Provider/实际协议适配夹具完成，无需购买第二厂商账号。夹具应覆盖编码、流式事件、工具结果、取消与 usage，不能只换两个模型名称。真实第二 Provider 接线另外保留验收状态。

T08 允许明确拒绝不可转换的跨协议 fork，并引导 fresh；需要测这一边界，不必为了“跨协议”盲目转发私有推理字段。第二厂商账号缺失不能阻止这些本地契约测试。

## 6 MCP 成员权限必须优先收紧

集成版本的 `MemberPermissions` 主要是写入/命令等开关；成员注册 MCP 工具后，MCP 授权端主要检查用户、服务配置与动作审批。这不足以证明路径、网络、账号和角色上限已经取交集。

- 扩展统一 ExecutionScope，携带团队、成员、任务 attempt、generation 和有效能力范围，并传到工具注册、审批、MCP 执行和资源解析。
- 注册阶段过滤工具，调用阶段再次检查当前权限；禁止通过旧工具句柄、目录更新或先批准后改参绕过限制。
- 权限覆盖原生与 MCP：文件路径、远程执行、网络目标、服务账号/scope、外部读写及未知副作用分别分类，不能用工具名是否含 write 或服务端 readOnlyHint 决定。
- 通用 MCP 参数无法保证任意外部服务器遵守本地路径/网络边界。受限成员只获得可落实约束的适配器、账号和服务；不能证明可控的远程执行/文件工具默认不下放。
- 人工批准也只能在已有上限内放行，不能覆盖父级禁止项。审批绑定真实成员、参数哈希、目标、配置 revision 与 generation。
- 验证“原生 bash 禁止，但 MCP 命令工具尝试执行”“只读成员调用远端写”“路径越界”“未授权域名”“旧批准复用”等负向场景，均需实际无副作用。

## 7 补丁一致性 用户交互与语义服务

补丁报告承认缺少锁和提交前摘要复验，存在读后到写前变化被覆盖的风险。这比只缺 diff UI 更优先：先统一 write/edit/patch/Team 发布的变更服务和版本保护，再补界面。

内部锁负责协调应用内竞争，内容哈希复验负责发现外部编辑；跨文件 journal 记录已应用集合及故障点。普通文件系统无法保证任意外部编辑器都参与锁，因此恢复只处理仍匹配本次 after 哈希的文件，其余保留冲突，不能承诺全局原子。

用户问题汇总、语言服务、来源卡片、作业/预览面板、diff/撤销和权限 UI 均属于原有交付要求。现有 TypeScript LanguageService 有真实价值，但加载范围和依赖诊断有边界，不能记成真实 LSP 生命周期通过。按原计划接 LSP 后端，保留现有工具契约与可复用编译器实现。

## 8 故障注入不需要建设通用 Bench

建立一个测试父进程，启动使用临时 SQLite、临时工作区和受控工具的独立服务子进程；通过测试专用屏障等待精确故障点，再终止子进程、重启并断言状态。故障开关只在测试配置可用，不能开放为生产 API。

至少覆盖：消息已持久化未注入、注入已提交未确认、工具外部效果已发生但结果未落库、多文件发布写完首文件、停止后迟到响应和旧 worker 租约过期。记录实际动作计数、文件哈希、消息注入次数、generation 和 unknown 状态。

杀进程不能只在内存抛异常，也不要用固定 sleep 猜时机。先用本地受控 HTTP/MCP 服务验证副作用计数，再运行真实容器进程收束场景；无需付费模型或任何通用性能/质量 Bench。

## 10 执行规则与完成判据

本节起是交给实施者的逐项执行卡。每张卡都必须交付代码、用户可操作入口或对应服务、测试与证据。文中路径是集成基线中的定位入口，允许重构位置，但交付报告必须说明最终位置。

### 状态只能按以下含义填写

| 状态 | 使用条件 | 不符合的情况 |
| --- | --- | --- |
| TODO | 尚未实现 | 不能填成环境阻塞 |
| PARTIAL | 已有部分实现或证据 | 不能计入通过数量 |
| FAIL | 实际运行不符合要求，或必需实现缺失 | 不能通过重命名用例消除失败 |
| BLOCKED | 外部账号、凭据或执行平台明确拒绝等真实前提不可用 | 缺代码、缺测试脚本、缺 UI、尚未选定实现均不属于此类 |
| PASS | 该原编号的全部要求满足，证据可复现 | 工具发现、接口 200、mock、截图文件存在不能代替端到端结果 |

每张 R 卡下的必需实现必须全部完成。已有 PASS 在实现和环境未变时可以引用原始证据；受本次修改影响的测试必须重跑。保留实际失败记录，不用重复尝试后的成功覆盖失败原因。

允许阻塞的常见范围只有：缺搜索凭据阻塞真实 Tavily 调用；确实无可用图片模型阻塞真实视觉回答；缺第二厂商凭据阻塞对应真实厂商 smoke；目标运行平台明确拒绝且不能在授权范围解决时阻塞其真实环境测试。上述情况均不阻塞本地协议测试、代码实现、UI、权限、迁移或故障注入。

## 22 R12 独立进程级故障注入

代码入口：新建集成测试父进程/fixture 服务、临时 SQLite 与工作区、现有 recovery、邮箱、租约、外部动作和发布 journal。

- [ ] 测试父进程启动唯一标记的服务子进程，以 IPC/管道/测试屏障等待精确故障点后 SIGKILL；不杀用户现有服务，不用全局 pkill，不用固定 sleep 作为故障定位。
- [ ] SQLite、媒体、工作区和受控 MCP/HTTP 副作用计数使用临时独立目录；子服务重启使用同一测试数据，真实验证持久恢复。
- [ ] 测试专用故障点只能在测试配置启用，正式服务不得接受远程“崩溃 API”。
- [ ] 每个故障用例记录 kill 前状态、进程结束、重启后状态、动作计数和资源清理；保存断言失败现场，脱敏后再归档。

必须运行以下故障矩阵：

| 故障位置 | 重启后的必需结果 |
| --- | --- |
| 消息已落库、尚未注入 | 后续可以消费一次，不漏信 |
| 消息已注入轨迹、消费确认未完成 | 不重复附加相同来源消息，游标/状态可恢复 |
| 外部工具已经产生效果、响应未入库 | 标为 unknown/待对账，不自动重复执行；受控服务动作计数为 1 |
| 多文件发布首文件已应用 | journal 准确列出已应用集合，剩余项未假报成功 |
| 发布中断后用户又改首文件 | 恢复不覆盖用户新内容，保留冲突证据 |
| 根运行停止后模型/工具迟到 | 不改成成功、不继续调工具、不发布产物 |
| 写成员旧租约到期、旧进程仍活跃 | 未确认终止前不重派同一写任务；旧代次不能提交 |
| 重启后模型/工具/凭据配置消失 | 明确阻塞与恢复入口，不静默换实现或重放动作 |

另测消息总量、自激唤醒、深度和并发上限，防止成员互相发送确认消息形成无界激活。故障测试使用本地可控模型与服务，无需通用 Bench 或收费模型。

完成证据：E05 的真实 kill/restart 输出、T18/T19/T27/T28/T49/T50 的原要求映射、最终文件哈希/副作用计数和测试进程全部退出。内存中抛异常只能作为补充单测。

## 25 最终报告格式与禁止替代

新增 `docs/features/eunoia-联调整改验收报告.md`，证据统一放 `docs/features/evidence/integration-acceptance/`。原报告保留历史，但在开头链接最新报告，不伪造原始测试时间或提交。

报告至少包括：

1. 基线和最终 commit、环境、脱敏配置、安装依赖与版本。
2. R01–R14 实现勾选及最终代码/API/UI 位置。
3. 原 D/T/V/E 编号、原要求、状态、测试命令、证据文件和失败原因；PASS/PARTIAL/FAIL/BLOCKED 分别统计。
4. 网络三条通道正负测试、截图入模、成员权限、补丁竞争、真实进程故障矩阵的独立证据。
5. 真实调用次数、输入输出、图片估算/实际 usage、搜索费用已知/未知情况；不消除失败调用的开销。
6. 备份迁移、构建、提交推送、重启后的运行身份和最终资源收束结果。
7. 仅由外部前提导致的剩余 BLOCKED，以及用户需提供的最小条件；其余缺口保持未完成。

以下情况不得算完成：

- 用环境说明代替本清单已确定的网关、LSP、截图导入或 UI 实现。
- 用新增一张图或纯 API 调用代替用户界面完整操作。
- 用模拟图片回答、文件路径或工具数量证明模型看到了图。
- 用安装语言服务器或编译器近似结果证明 LSP 取消/重连已通过。
- 用扩大全部网络、授予全权限、关闭审批或全局 chmod 解决集成失败。
- 用降低预算外检查、删除失败测试、改变编号或改写需求得到全绿。
- 用“需要另一轮版本”“本次时间不够”“已有模块以后再接线”省略必需交付。
