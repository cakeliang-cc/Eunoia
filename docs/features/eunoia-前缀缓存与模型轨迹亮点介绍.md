# Eunoia 前缀缓存与模型轨迹亮点介绍

日期：2026 年 11 月 8 日。代码基线：`824d369` + 本次模型轨迹提交。本文用于项目
介绍、面试讲解及后续更新；「已实现」以 ADR 032 与验收报告为准。

Eunoia 把稳定提示词、动态背景、聊天消息和模型回放轨迹分开管理。稳定提示词一次
加载并按实际文本取版本；动态背景按命名块比较，只追加变化；模型轨迹把用户内容、
背景更新、分步助手输出、reasoning 和工具结果按顺序持久化。普通回合保持同一阶段
的前缀，压缩、重生、停止恢复或换模型时建立显式新阶段。

## 1 一句话说明这一块解决什么

Agent 每次请求都要向模型提交上下文。我们关注三个问题：之前处理过的内容能否复用
计算、当前状态有没有准确更新，以及上下文接近窗口上限时如何继续。

前缀缓存复用供应商已经计算过的提示词开头；Harness 负责组织请求、维护状态和控制
窗口。命中缓存可以降低输入费用和预填充计算，但被缓存的 Token 仍然属于输入，也
仍占窗口。

## 2 当前已经实现到哪里

| 能力 | 当前实现 | 可以怎样介绍 |
|---|---|---|
| 稳定提示词 | `instructions.ts` 启动加载文档、去注释、以实际文本计算版本 | 提示词可追踪版本；动态时间/记忆不混入固定提示词 |
| 结构化动态背景 | `context-projection.ts` 按固定 key/scope 渲染；未变不追加、变化追加快照、清空发 tombstone | 状态变化可解释；不是每轮重发一大段背景 |
| 可持久化模型轨迹 | `model_items` 保存实际提交顺序；图片只存 assetId；工具结果保存模型收到的有界全文 | 跨轮和重启不靠 UI 气泡猜模型历史 |
| 阶段与状态基线 | `model_epochs`、`model_context_state`、`model_steps` | 普通轮次同阶段；压缩/换模/提示词变化有原因和边界 |
| 原生工具循环 | 固定本轮工具 schema；输出、调用、结果按序保存后再发下一步 | 多步工具交互可回放，回放本身不执行工具 |
| 每请求预算 | 循环每一步重新检查；裁剪提交新的活动窗口 | 工具结果增长后仍重新检查窗口，超限有明确结束原因 |
| 执行审计与恢复 | turn 与工具事件落库；未知结果保留 unknown；未配对调用建立恢复边界 | 知道执行到哪里，恢复不会自动重跑有副作用的工具 |
| 图片发送与预算绑定 | 固定媒体计划，计数和编码同一发送变体；轨迹引用媒体资产 | 避免按小图计数却发送大图；图片估计与真实 usage 分开 |
| 逐请求 usage | `model_steps.usage` + `turn_usage` 汇总 | 区分末步、整轮、未知字段与窗口估计 |
| usage 与实验 | 真实 DeepSeek 长回复对照 + 新轨迹 live smoke | 用实际 usage 判断收益，同时报告输入长度和总费用 |

旧库第一次开启 durable 时以现有摘要和 user/assistant/图片创建一次 `legacy-seed`
基线；旧轨迹不完整这一点如实标记，不能从 2000 字符审计片段虚构完整工具结果。

## 3 最值得讲清楚的现有设计

### 聊天消息和模型轨迹是两份事实

`messages` 服务 UI、搜索和导出；`model_items` 回答「模型此前具体看到/产生了什么、
顺序如何」。两者通过 messageId、requestId、callId、step 关联，不互相覆盖。这样
重新生成可以回退活动视图而不抹掉审计，重启也可以从同一份条目恢复。

### 稳定内容、持续状态和本轮资料分开

固定提示词一次加载；关系、叙事、权限、目录、技能、工具说明、时钟是持续块，同
key 只在变化时追加快照；本轮记忆/附件/继续指令/安全指令带着 requestId，下一回合
自动失效。时钟按分钟粒度去重，循环内不每步刷新。

背景在 wire 上可以是 user 角色，以保持更好的前缀顺序；但预算保护、用户计数和
回合边界按服务端产生的 `source` 判断，不依赖 `role === 'user'`。

### 普通轮次和阶段边界

同一 epoch 内条目只追加。压缩、有效历史回退、提示词/工具声明变化、模型/provider/
编码版本变化、停止恢复、安全替换、未配对工具调用，都会建立新 epoch 并记录原因。
新 epoch 可以引用旧条目，但活动窗口是一个明确的有序视图；旧条目保留到删除或保留期
清理。

### 同时管理费用和窗口

缓存输入通常更便宜，但不是免费上下文。循环内工具返回越来越多时，预算器仍要重新
计算，并先压缩旧工具结果、成组裁剪旧历史，最终放不下时明确停止。裁剪一旦发生就
提交新的活动窗口修订，下一步和重启沿用同一视图；原始结果仍可审计，但不自动重新
进入活动输入。

### 恢复以执行事实为依据

工具调用在运行前落库，结果返回后落库。进程在发送中崩溃时状态是 unknown；活动
窗口里没有配对结果的调用不会再次发给模型，而是进入恢复边界，用有来源的中断说明
替代。重新生成不会回滚已经发生的文件修改或命令，也不会因为回放重跑工具。

## 4 已完成的真实对照可以证明什么

### 旧实验：16 请求长回复对照

已有对照使用真实 `deepseek-flash` Responses API，两个 4 轮组，交换两种方案的运行
顺序，共 16 次请求。每次实际输出 1025–1030 Token，并逐字回填下一轮，没有以简短
固定句替换 assistant。

| 指标 | 当前结构 | 实验中完整保留背景 |
| --- | ---: | ---: |
| 请求数 | 8 | 8 |
| 累计输入 Token | 45,146 | 47,836 |
| 累计命中 Token | 25,088 | 34,560 |
| 累计未命中 Token | 20,058 | 13,276 |
| 加权命中率 | 55.57% | 72.25% |
| 累计输出 Token | 8,220 | 8,204 |
| 输入参考费用 | $0.003083964 | $0.002095080 |
| 包含输出的参考费用 | $0.008015964 | $0.007017480 |

在这组样本中，输入长度增加 **5.96%**，输入参考费用减少 **32.07%**，包含输出的
总参考费用减少 **12.46%**。参考单价为每百万缓存输入 $0.003、未命中输入 $0.15、
输出 $0.6；是统一口径折算，不是账户扣费核对。

它说明长助手回复的前缀复用值得优化，但没有证明生产固定节省 32%，也没有覆盖真实
工具执行、reasoning 回放、图片或长会话压缩。

### 新 smoke：真实路由的模型轨迹

本次在真实 `deepseek-flash` 上跑了 S01–S03（详见
[验收报告](./eunoia-模型轨迹与前缀缓存验收报告.md)）：

- **S01**：4 组 × 3 轮，交换 legacy/durable 顺序，12 次请求。durable 输入长度
  **+36.46%**，含输出总参考费用 **−2.47%**。净收益很薄，不能宣称固定节省。
- **S02**：一次真实工具往返，模型调用 `live_probe` 1 次、结果返回 1 次，回复原样
  引用随机 marker；回放没有执行工具。
- **S03**：同一会话关闭并重开 store；仍是同一 epoch，第二轮工具调用 0 次；时钟
  从 10:00 到 10:05 追加了 revision 2 的状态块。

新 smoke 的样本小、只覆盖文本和短会话。它证明真实路由和恢复路径可用，不证明长期
生产收益。

## 6 用一个例子介绍目标行为

1. 用户让 Agent 分析代码，助手输出一段长回复；模型实际看到的背景、回复与工具结果
   按原顺序保存。
2. 用户接着提问，目录和权限未变。持续背景不重复追加，旧轨迹仍在前面，有机会被
   供应商缓存复用。
3. 用户把工作目录改到 backend。`change_directory` 成功结果附带 `cwd`，轨迹追加一个
   有版本的工作目录状态块；旧目录保留为历史，新目录成为当前状态。
4. 会话达到预算后，压缩旧的完整回合成检查点，保留近期轨迹并重建最新状态；下一段
   前缀重新建立缓存。
5. 进程重启，读取已经保存的轨迹。之前执行过的工具只作为历史数据回放，不再次执行；
   如果上次崩溃留下未配对调用，会用恢复边界替代它，说明结果未知。

## 7 面试和项目介绍话术

### 当前可以使用的版本

> 我在 Eunoia 里把稳定提示词、动态背景和模型轨迹分开。固定提示词按实际文本取版本；
> 关系、权限、目录、时钟等背景按命名块比较，未变不追加、变化追加快照、清空有
> tombstone。模型实际看到的用户内容、分步助手回复、reasoning 和工具结果按顺序存
> 到 SQLite，跨轮和重启按同一份条目回放；压缩、重新生成或换模型时显式开启新阶段。
> 每次请求单独记 usage，整轮只汇总已知值并标记缺失。真实 DeepSeek 长回复对照里，
> 旧实验输入费用下降约 32%；新轨迹 smoke 的 S01 是输入长度 +36%、总费用 −2.47%，
> 所以我把收益说成样本结果，不承诺固定节省。

### 涉及真实供应商和费用时的补充

> S01–S03 已经跑过真实 `deepseek-flash`：工具往返和重启恢复都通过。不过样本只有
> 3 轮、没有长会话压缩和图片，费用是参考单价折算。生产上默认是否开启 durable、
> 如何回滚、旧库如何 seed，都写进了 ADR 032。

## 8 常见追问

**为什么不能简单把所有旧背景一直带着？**

它能帮助前缀连续，但会积累重复内容、过时状态并占据窗口。计划方案对持续状态按变化
追加，对本轮资料声明作用域，再通过预算和摘要控制增长。

**模型已经输出过的 assistant，为什么下一次还要带？**

每次请求要有可用上下文。带上助手历史与维持其前面的内容顺序是两件事：即使回复原文
没变，删除它前面的旧背景，也可能损失相应前缀的缓存复用。

**缓存是不是保存在我们数据库里？**

数据库保存的是轨迹和状态；供应商服务端保存可复用的计算状态。我们组织请求争取复用，
但不能保证缓存没有过期或被淘汰。

**命中率从 55.57% 升到 72.25%，是不是只省了 16.68%？**

这是提高了 16.68 个百分点，不是费用降幅。费用要按绝对命中量、未命中量和对应单价
计算，还要加上输出和摘要等调用成本。

**换模型以后，缓存能直接搬过去吗？**

不能承诺。可移植消息可以重新投影，供应商的 KV 缓存和私有推理签名通常不能直接复用；
方案会明确开启新阶段，兼容性不成立时给出错误。

**为什么有工具日志还需要模型轨迹？**

审计回答执行事实，保留有界片段即可；模型轨迹要回答此前具体提交了什么、顺序如何。
当前 2000 字符审计上限不足以保证精确回放，所以两者有不同契约。

**为什么 durable 的输入更长，费用却更低？**

因为更多输入落在供应商缓存命中的部分，未命中输入减少。S01 里输入长度 +36.46%，
但未命中 Token 与含输出总费用略降。只看命中率或只看输入长度都会误判。

## 9 当前核对与后续更新

本次离线验收与既有回归合计 **1371 passed / 27 skipped**（全量 `npm test`）；类型
检查、lint、build 通过。新增的 A01–A32 用例分布在：

```sh
npm test -- tests/session/model-transcript.test.ts tests/db/model-transcript.test.ts \
  tests/agent/context-projection.test.ts tests/agent/model-replay.test.ts \
  tests/service/model-replay.test.ts tests/agent/model-turn.test.ts
```

真实 smoke 结果文件保留在
[experiments](../research/prefix-cache/experiments/)，旧 16 请求实验原始数据没有被覆盖。当前限制：

- 代码默认仍是 `legacy`；本部署在 `.env` 显式启用 `durable`，回滚只需改回 legacy。
- 旧轨迹无法恢复完整工具输出；seed 只基于现有摘要与消息。
- 没有新的统计面板；诊断通过日志、`transcriptDiagnostics()` 与实验脚本导出。
- 费用均为参考单价折算，不是账单。
