# 外部服务（MCP）

Eunoia 可以连接 MCP（Model Context Protocol）服务：把外部工具交给模型，读取资源与
提示词，让你在写入前确认。外部工具与内置工具走同一条执行管线——同一套参数校验、
权限、事件、预算和模型轨迹——但它们的执行发生在别的进程或远端，所以有自己的账户、
目录和生命周期。

设计见 [ADR 033](../adr/033-mcp-host.md)，逐项验收见 [验收报告](./acceptance.md)。

> 默认没有任何外部服务。所有服务器默认不启用；配置并授权后才可用。

## 1 能做什么

| 能力 | 说明 |
| --- | --- |
| 工具 | 发现、筛选、调用；模型看到的是 `mcp__服务_摘要__工具名` |
| 结果 | 文本、结构化内容、图片、资源链接、嵌入资源；非图片二进制进入私有产物 |
| 资源 | 列表、模板、读取；用户选入后成为本轮上下文快照 |
| 提示词 | 列表、参数校验、获取与预览；不自动覆写系统指令 |
| 审批 | 写操作和未知副作用在调用前暂停，批准只对那一次动作有效 |
| 补充信息 | 服务器可以请求表单或 URL；密码类字段不会被普通表单收集 |
| 长任务 | 保存远端任务句柄，提供查询与取消入口 |
| 认证 | 匿名、环境变量引用、Bearer、自定义头、OAuth 登录 |
| 传输 | stdio（宿主或容器）与 Streamable HTTP |

## 2 添加一个服务

打开顶部 **外部服务** → **添加**。

### 2.1 HTTP 服务

| 字段 | 说明 |
| --- | --- |
| 服务地址 | 必须 `https`；本机/私网地址要部署显式允许 |
| 认证 | 匿名 / Bearer / 自定义头 / OAuth |
| 凭据引用 | 形如 `env:MCP_DOCS_TOKEN`，只写引用，不写值 |

在 `.env` 或部署环境里设置变量（必须以 `MCP_` 或 `EUNOIA_MCP_` 开头）：

```sh
MCP_DOCS_TOKEN=your-token-here
```

不要在配置文件里写真实 token。应用只存引用，且不会把值读回管理接口。

### 2.2 stdio 服务

| 字段 | 说明 |
| --- | --- |
| 可执行文件 | 只写一个程序，例如 `node`；不经过 shell |
| 参数 | 每行一个 |
| 运行位置 | `沙箱容器`（默认）或 `宿主进程`（需要部署允许） |
| 环境变量引用 | 每行 `NAME=env:MCP_NAME` |

宿主进程模式必须由部署打开：

```sh
MCP_ALLOW_HOST_PROCESS=1
```

打开后管理界面会显示“宿主进程”。这是受信模式，**不是沙箱**；模型和普通会话审批
都不能打开它。

沙箱模式需要 Docker，以及一个 digest 固定的镜像（`name@sha256:…`）。主机用
`docker run -i` 启动受控容器：无网络、只读根、drop capabilities、固定 UID、
内存/CPU/PID 限制；环境变量按名传入，不出现在 argv。

### 2.3 从 mcpServers JSON 导入

在抽屉底部粘贴常见的 `mcpServers` 文档，先 **预览**：

- 同一个校验器解析，非法字段会说明原因；
- `${VAR}` 与 `env:VAR` 变成引用；
- 裸字面量会被改成 `env:<字段名>` 并提示你设置变量——导入不会把 token 写进数据库；
- `sse` / `websocket` 被跳过并说明原因；
- 导入的服务默认不启用。

## 3 让它工作

1. 添加后在列表点 **连接**；
2. 看到“可用”与工具数后，在对话底部选择该服务（或留空表示使用所有已启用服务）；
3. 发一条会用到它的消息；
4. 如果工具需要审批，聊天里会出现“需要你批准”的卡片；抽屉里也有同样的待处理项。

刷新页面不会丢失待处理项；同一动作只能被批准一次。

## 4 权限与审批

- **只读**：分类来自应用策略。默认不信任服务器的 `readOnlyHint`；即使信任，也只
  改变分类，不自动放行。
- **写入**：只有你明确批准才执行。批准绑定服务、账户、工具、契约摘要、参数摘要和
  过期时间；参数或契约变了，旧批准失效。
- **未知副作用**：默认按写入处理。
- “只读调用不询问”是一个显式选项；写操作永远不会被它放行。
- 拒绝/取消/超时都不会产生远端调用；超时之后迟到的批准不会执行。

## 5 资源与提示词

- 资源读取只允许目录里列出的 URI 或已声明模板生成的 URI；`file://` 不会被当成本机
  路径，内网 HTTP 也不会被隐式抓取。
- “选入上下文”会保存一份快照；服务器之后说资源变了，不会改写已经在历史里的快照。
- 提示词只做预览；应用时作为带来源的本轮模板，不替换系统提示词，也不伪造历史消息。

## 6 认证

### Bearer / 自定义头

配置只存 `env:NAME`。连接时解析，值登记到进程级脱敏器，错误、结果与 stderr 在
入模/落库前都会被替换。缺变量时显示“需要登录/缺少环境变量”，不会假装匿名可用。

### OAuth

- 支持预注册客户端、客户端元数据文档和动态注册（由 SDK 按协商能力选择）；
- 回调固定为 `http://127.0.0.1:<port>/api/mcp/oauth/callback`，只接受 loopback；
- state 一次性且与服务绑定；跨服务兑换 code 会被拒绝；
- token 加密存储（AES-256-GCM），AAD 绑定 owner/server/类型/版本；
- 退出登录会删除凭据并回到“需要登录”。

需要主密钥：

```sh
# 32 字节，base64 或 64 位 hex
EUNOIA_MCP_KEY=...
# 或
EUNOIA_MCP_KEY_FILE=/path/to/mcp-key
```

没有主密钥时，匿名与 env 引用服务仍可用，但 OAuth token 不会被保存（也不会退回明文）。

## 7 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 状态一直“需要登录” | 缺少凭据变量，或 OAuth 未完成 | 检查 `MCP_` 变量；重新登录 |
| “连接失败：stdio 服务需要的环境变量没有值” | 引用的变量缺失 | 设置变量后重新连接 |
| “沙箱启动被这个部署关闭” | 未安装 Docker 或部署禁用 | 安装 Docker，或由部署显式打开宿主模式 |
| “工具目录在本次回合中发生了变化” | 服务器更新了工具 | 重试；旧授权不会转发到新契约 |
| “图片无法导入” | 格式/大小/解码失败 | 查看诊断；不会伪造模型已看图 |
| 服务不可用但对话还能继续 | 它是 optional | 想让它阻塞回合就勾选“必需” |
| 管理接口 403 | 缺少本地控制令牌 | 通过本地服务地址打开页面 |

日志按 `actionId` / `serverId` / `catalogRevision` 关联；不记录 secret、Authorization、
Base64 或完整参数正文。

## 8 卸载与清理

1. 在列表里 **断开** 服务；
2. **删除** 服务（两次点击确认）：先停用并撤销新执行，再关闭连接、删除凭据与目录；
3. 历史调用仍可审计到服务墓碑，但不再有可用认证；
4. 删除会话/用户会级联清理动作、待处理项、任务句柄、资源快照与媒体引用；
5. 备份包含数据库与媒体文件，但**不包含** `EUNOIA_MCP_KEY`；恢复后 OAuth 服务需要
   重新登录。

## 9 开发与测试

```sh
npx vitest run tests/mcp tests/service/mcp-turn.test.ts tests/api/mcp.test.ts
npm run browser:check   # 含 MCP 抽屉的 390px/桌面截图
```

真实 stdio fixture 在 `tests/fixtures/mcp-stdio-server.mjs`。它会把每次调用写入
`FIXTURE_LOG`，测试据此证明“批准前 0 次、批准后 1 次”。
